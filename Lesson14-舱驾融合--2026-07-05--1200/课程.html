舱驾融合——座舱和智驾怎么"共享一个大脑"？

← 上一课 ☰ 目录 下一课 →

一、先想想这个问题

过去，一辆智能汽车里有两个"独立大脑"：

  • 座舱域控制器负责中控屏、仪表盘、语音助手、导航——这是给"人"用的。
  • 智驾域控制器负责摄像头感知、路径规划、刹车/加速控制——这是给"车"用的。

它们各自有独立的芯片、独立的内存、独立的操作系统，甚至来自不同的供应商。

问题：为什么不把这两个"大脑"合并成一个？合并后会遇到哪些麻烦？

今天的重点：舱驾融合（Cockpit-Domain Integration）——将座舱域和智驾域的功能整合到同一个域控制器或同一颗 SoC 上，实现"一个大脑管所有"。

二、为什么要合？三个驱动力

#驱动力说明量化收益
1成本降低两颗芯片→一颗芯片，减少 PCB 面积、散热、外壳、线束硬件 BOM 成本降低 30~40%
2数据共享座舱需要智驾的感知数据做"增强现实导航"；智驾需要座舱的语音和 DMS 数据跨域通信延迟从 10ms 降到 <1ms
3软件升级一个操作系统、一套 OTA 流程、一次开发测试周期软件开发成本降低 ~50%

数据共享的典型场景

场景举例：当智驾检测到前方有行人突然横穿，不仅智驾会触发 AEB（自动紧急刹车），座舱的 AR-HUD 会立刻在挡风玻璃上高亮标注行人位置，同时语音播报"前方有行人请注意"。这一切如果靠两个域控制器的 CAN 通信实现，延迟至少 10~20ms；融合后只需要 <1ms。

三、怎么合？三种技术路线

路线 A：硬件融合——一颗 SoC 跑两个域

特性说明
典型芯片高通 SA8775 / SA8797、英伟达 Thor、地平线 J6
架构一颗 SoC 内部通过硬件虚拟化分割为两个"安全岛"：一个跑座舱 OS（Android/QNX），一个跑智驾 OS（RTOS/Linux+Safety）
隔离方式Hypervisor（虚拟机监视器）——硬件级别的资源隔离，确保智驾的实时任务不被座舱 UI 动画干扰
优势成本最低、通信延迟最低、PCB 面积最小
挑战功能安全隔离——座舱出 Bug 不能影响智驾；需要芯片支持硬件虚拟化
flowchart TB subgraph SOC["一颗 SoC"] subgraph HV["Hypervisor 硬件虚拟化层"] DIR1["虚拟分区 1"] DIR2["虚拟分区 2"] end subgraph COCKPIT["座舱域"] ANDROID["Android / 鸿蒙"] NAVI["导航"] MEDIA["多媒体"] VOICE2["语音"] end subgraph ADAS["智驾域"] RTOS["RTOS / Safe Linux"] PERCEPTION["感知（目标检测）"] FUSION2["融合"] CONTROL["控制（AEB/LCC）"] end end SOC --> HV HV --> COCKPIT HV --> ADAS

路线 B：板级融合——两颗 SoC 在同一块板子上

特性说明
方案一块 PCB 上放两颗芯片：一颗高性能 SoC 跑座舱，一颗安全 SoC/MCU 跑智驾
互联通过片内高速总线（PCIe / 以太网）直连，延迟 1~5ms
优势保留了各自的硬件独立性（满足功能安全），又避免了跨域控制器的物理线束和外壳成本
挑战仍比单 SoC 方案贵，散热设计复杂

路线 C：域控级融合——两个域控制器合并在一个"盒子"里

特性说明
方案一个盒子里有两块独立板卡（座舱板 + 智驾板），共用电源、外壳、散热，板间走车载以太网
优势供应商解耦——座舱板 A 公司供货，智驾板 B 公司供货，OEM 组装；已有成熟量产
挑战成本节省有限，不是真正融合

行业趋势：2024~2026 年是"路线 C → 路线 B"的过渡期；2027~2030 年主流是"路线 A"（单 SoC 硬件虚拟化）。英伟达 Thor（2025 年量产）和高通 SA8775（2024 年量产）都支持路线 A。

四、核心难点：功能安全隔离

舱驾融合最大的技术挑战不是"能不能合一"，而是"合一后智驾还能不能安全运行"。

功能安全等级差异

域安全等级要求
智驾域ASIL-D（最高等级）单点故障失效率 < 10⁻⁸/小时；AEB/ACC 失效可能导致死亡事故
座舱域QM（无安全要求）中控屏死机不会导致行车事故；导航地图卡顿最多让用户烦躁

核心矛盾：把 QM 级别的系统和 ASIL-D 级别的系统放在同一颗芯片上运行——座舱的一个内存泄漏 Bug 可能导致智驾系统无响应，车就失去了自动刹车能力。

解决方案

技术作用
硬件虚拟化（Hypervisor）硬件级别隔离内存、中断、外设。智驾分区不能访问座舱分区的内存，座舱分区也不能抢智驾分区的 CPU 时间
TLB 隔离 & MPU内存管理单元（MMU）和内存保护单元（MPU）确保两个域的内存空间完全独立
安全岛（Safety Island）芯片内部专门划出一个"安全核心"跑智驾安全监控，独立于主处理器核心
时间确定性调度智驾的 AEB 控制任务必须在 1ms 内完成；如果座舱的动画特效抢了 CPU，调度器必须优先保障智驾

五、三条核心规则

#规则一句话
1融合的驱动力是成本和数据共享把座舱和智驾放在一个域控/SoC 上，省了芯片钱和线束，还让数据互通延迟从 10ms 降到 <1ms
2融合的最大障碍是功能安全隔离ASIL-D（智驾）和 QM（座舱）的安全等级差了一个数量级，必须用硬件虚拟化、安全岛等技术隔离
3行业正在从"物理合一"走向"芯片合一"2024 年板级融合为主流，2027 年后单 SoC 硬件虚拟化将成为行业标准
