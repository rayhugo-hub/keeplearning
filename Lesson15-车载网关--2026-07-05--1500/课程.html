车载网关的网络安全——网关如何守住汽车的第一道防线？

← 上一课 ☰ 目录 下一课 →

一、先想想这个问题

想象一下：你正在高速上以 120km/h 行驶。这时，一辆停在路边的攻击车通过 Wi-Fi 接入了你的车载网关，然后向 CAN 总线发送了一条伪造的"刹车解除"指令——你的刹车踏板瞬间变软了。

这不是科幻片，这是真实的安全研究案例。 2015 年，两位研究员 Charlie Miller 和 Chris Valasek 通过克莱斯勒 Uconnect 系统的 4G 漏洞远程攻入了一辆 Jeep Cherokee 的网关，在高速上控制了刹车和转向。这直接导致克莱斯勒召回 140 万辆车。

今天的重点：车载网关的网络安全——网关为什么是汽车的第一道防线？它都面临哪些攻击？用什么技术防御？

二、网关为什么是安全核心？

回顾 Lesson 01：车载网关是汽车网络的中枢，它连接着外部通信（4G/5G、Wi-Fi、蓝牙、GPS）和内部网络（CAN FD、CAN、LIN、车载以太网）。

flowchart TB EXT["🌐 互联网 / 云<br>(4G/5G/T-BOX → 云平台)"] TBOX["📡 T-BOX<br>(Modem)"] GW["🛡️ 车载网关"] CANFD["CAN FD<br>(动力/底盘)"] ETH["车载以太网<br>(ADAS/座舱)"] LIN["LIN/其他<br>(车身控制)"] EXT --> TBOX TBOX --> GW GW --> CANFD GW --> ETH GW --> LIN

网关就是内外之间的"唯一通道"。 所有从外部进来的数据都必须经过网关——这意味着只要守住网关，外部攻击就无法直接触及 CAN 总线。反过来，如果网关被攻破，整车网络就完全暴露。

角色说明
唯一入口所有外部通信（4G/蓝牙/Wi-Fi/车载以太网诊断）都经过网关
协议转换点外部来的 IP 数据包→内部 CAN 帧，转换点是最容易被攻击的点
路由决策点网关决定哪些消息可以转发、转发到哪里——防火墙功能就做在这里
安全审计点网关是部署入侵检测系统（IDS）的最佳位置

三、五大攻击场景

#攻击路径手段后果
1远程攻击通过 T-BOX 的 4G/5G 漏洞远程入侵网关全球范围可攻击，无需物理接触
2Wi-Fi/蓝牙攻击破解 Wi-Fi 密码或通过蓝牙配对漏洞进入近距离（几十米内）可攻击
3OBD-II 诊断攻击通过 DoIP（Diagnostics over IP）接口直接访问网关物理接触，但 OBD 接口通常暴露在车内
4无线传感器欺骗伪造 TPMS（胎压监测）或 RKE（遥控钥匙）信号导致错误告警或车门被非法打开
5供应链攻击在 T-BOX 或网关固件的生产环节植入后门最隐蔽，难以发现

2015 Jeep 事件回顾： Miller 和 Valasek 通过 Sprint 4G 网络找到了 Jeep 的 IP 地址（Uconnect 系统有公开 IP），利用系统漏洞获得了 T-BOX 的 shell 权限，再通过 CAN 总线注入伪造消息——即使车没有点火，也能控制雨刷、音响、转向和刹车。

四、四大防御技术

防御 1：网络隔离与防火墙

网关内部有多个"安全域"，域之间通过访问控制列表（ACL）控制通信：

安全域包含网络外部可访问？
❗不可信域T-BOX、Wi-Fi、蓝牙、OBD-II✅ 是
⚠️ 低安全域信息娱乐 CAN（IVI）✅ 受限
🟡 中安全域车身 CAN（BCM、车窗、门锁）❌ 否
🔴 高安全域动力 CAN FD（发动机、变速箱、刹车）❌ 否
🟢 诊断域DoIP（OBD-II 诊断）✅ 认证后

防火墙规则示例：

规则 1: 不允许 不可信域 → 动力 CAN FD（任何消息）
规则 2: 不允许 不可信域 → 车身 CAN（除授权诊断外）
规则 3: 允许 不可信域 → 信息娱乐 CAN（媒体流）
规则 4: 动力 CAN FD → 车身 CAN（速度信号）允许
规则 5: 诊断仪需证书认证后才可访问动力 CAN FD

防御 2：入侵检测系统（IDS）

类似 IT 网络的"杀毒软件"，车载 IDS 监控 CAN/以太网总线上的消息流，发现异常行为：

检测类型检测什么举例
频率检测某个 CAN ID 的发送频率是否异常速度信号正常情况下每 100ms 发一次；如果突然每秒发 1000 次→可能是攻击
值域检测信号值是否超出合理范围车速信号值从 120km/h 突然跳到 1000km/h→异常
序列检测CAN 消息的顺序是否异常正常情况下 A→B→C 的顺序，如果跳过了 B→怀疑攻击
认证检测可疑的远程登录尝试同一个 IP 在 1 秒内尝试 100 次登录→暴力破解

防御 3：安全启动（Secure Boot）

问题： 如果攻击者修改了网关的固件，替换成恶意版本，那么所有防火墙规则都形同虚设。

Secure Boot 的工作原理：

sequenceDiagram participant HW as 🔲 硬件 BootROM participant Boot1 as 📦 Bootloader 1<br>(一级引导) participant Boot2 as 📦 Bootloader 2<br>(二级引导) participant OS as 🖥️ 网关 OS/固件 Note over HW,OS: 安全启动链——层层验证，一环破→整体停 HW->>HW: 烧录在芯片内的根公钥<br>（不可修改的硬件密钥） HW->>Boot1: 读取 Bootloader 1 及其签名 HW->>HW: 用根公钥验证 Boot1 签名 Note over HW: 签名验证通过？✅ HW->>Boot1: ✅ 启动 Boot1 Boot1->>Boot2: 读取 Bootloader 2 及其签名 Boot1->>Boot1: 用 Boot1 中公钥验证 Boot2 签名 Note over Boot1: 验证通过？✅ Boot1->>Boot2: ✅ 启动 Boot2 Boot2->>OS: 读取 OS/固件及其签名 Boot2->>Boot2: 用 Boot2 中公钥验证 OS 签名 Note over Boot2: 验证通过？✅ Boot2->>OS: ✅ 启动 OS Note over HW,OS: 任何一步签名失败 → ❌ 停止启动 → 进入恢复模式

关键点：

  • 第一级信任根（Root of Trust）烧录在芯片硬件中，无法被软件修改
  • 每一级启动前都验证下一级的数字签名
  • 如果签名验证失败，芯片进入安全恢复模式（只接受经过签名的官方固件刷写）
  • 确保即使攻击者拿到物理芯片，也无法运行自定义恶意固件

防御 4：安全 OTA 更新与证书管理

要求实现方式
固件完整性每次 OTA 镜像必须带有 OEM 的数字签名，网关验证签名后才刷写
防回滚网关记录当前固件版本号，禁止刷写比当前版本更旧的固件（防止攻击者刷回有漏洞的老版本）
加密传输OTA 镜像全程 TLS 加密传输，防止中间人攻击
原子更新刷写过程中断电→网关能恢复到上一个可用版本（A/B 分区方案）

五、三条核心规则

#规则一句话
1网关是汽车网络安全的唯一关口所有外部数据都必须经过网关，守住网关就守住了整车网络；网关被攻破，整辆车沦陷
2用"纵深防御"替代"单点防御"防火墙+入侵检测+安全启动+安全OTA，四层防御层层递进，单层突破并不意味着整车沦陷
3汽车网络安全和 IT 网络安全有本质区别汽车 CAN 总线没有认证和加密机制（30年前的协议），网关需要额外保护；攻击后果不只是"数据泄露"，而是"人命关天"
