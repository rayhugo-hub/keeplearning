车载以太网帧抢占——快车凭什么能"抢道"，被切成段的慢车还不丢数据？

费曼简答题参考答案

Q1：用"高速公路应急车道"打比方：为什么 Qbv 时间窗之间要留"保护带"？这个保护带为什么必须按"最长的大货车"来留？帧抢占是怎么把这段空档从"一辆大货车"缩短到"一小段"的？

核心思路：帧一旦开头发就不能停 → 只能用"最大帧"当空档 → 切小普通帧，空档就只需按"最小分片"留。

① 为什么需要保护带：

  • Qbv 把出口时间切成一段段"时间窗"，关键流有专属窗口。但以太网有一条硬规则：一个帧一旦开始发送，就必须完整发完（包括前导码和尾部 CRC），中途不能被谁打断。
  • 于是危险发生在"换窗的瞬间"：如果普通时段快结束时刚开始发一个 1500 字节的大帧，它会越界撞进下一个关键窗口，把关键帧往后推——关键帧就算有专属时间窗，也进不来（通道还被占着）。
  • 解决办法是保护带：在关键窗口开始前留一段"不允许开始发新帧"的时间，让"已经在传的帧"在这段时间里发完。它是"给正在路上的车留出驶离时间"，不是"禁止通行"。

② 为什么必须按"最长的大货车"留：

  • 保护带要保证"任何一帧都能在此时间内发完"。以太网里最长的帧是带一个 VLAN 标签的 1500 字节帧：1500 + 18 + 4 + 12 + 8 = 1542 字节。
  • 所以保护带长度 = 发送 1542 字节所需时间。100 Mbps 下约 123.36 µs。
  • 代价：每个周期、每个关键窗口前都要空出这段时间，这段时间一个字节都发不出去——带宽白扔、周期压不下去。就像高速上每次都按"最长货车"留空档，普通车流的通行效率被大幅拉低。

③ 帧抢占怎么把空档缩短：

  • 关键洞察：如果正在传的车能在半路"靠边停一下"，就不需要按整车长度留空档了。 帧抢占就是让正在传的普通帧在安全的切点停下来、先让关键帧整帧通过，然后再从断点续传。
  • 切点有粒度限制：硬件以 64 字节为单位检查"要不要让路"，且非末分片至少 64 字节。所以最坏情况下有 63 字节已经发出、来不及切，加上 64 字节的最小分片，残余保护带 = 64 + 63 = 127 字节。
  • 100 Mbps 下 127 字节只有约 10.2 µs，比 123 µs 缩短 90% 以上。省下的时间就是可用带宽，周期也能做得更短。

结论（类比落点）： 保护带是"给最长货车留的驶离空档"；帧抢占让普通车学会"靠边停、分段走"，于是空档只需按"最小一段车"留——从 1542 字节降到 127 字节。

Q2：帧抢占把一个正在传的普通帧"切成几段"，可接收端怎么知道"这半截是分片、后面还有"？前导码和 CRC 各被改了什么？为什么链路上必须先"报备 + 验货"？

核心思路：用前导码里的 SMD 标志区分"快车 / 分片开头 / 续片"，用 mCRC 与 FCS 的区别区分"分片"与"整帧结束"；改了帧格式，就必须先确认对端也认识这套格式。

① 前导码被改了——用 SMD 表明"这片的身份"：

  • 普通以太网帧的前导码最后 1 个字节是 SFD（0xD5），表示"一个帧开始了"。帧抢占把这个位置换成 SMD（Start of mPacket Delimiter）：
    • SMD-E：这是一个快车（eMAC）整帧——优先级最高、不可被抢；
    • SMD-S：这是一个分片的开头（后面还有）；
    • SMD-C：这是一个分片的续片；
    • 另有 SMD-V / SMD-R（verify / respond），专供链路两端"验货握手"用。
  • 接收端一看到前导码里的 SMD，立刻知道"我正在收的是一整帧，还是某帧的一部分"。

② 尾部校验被改了——mCRC 与 FCS 的区别就是"还有没有后文"：

  • 普通帧尾部是 FCS（CRC-32，对整帧计算）。
  • 帧抢占里：非末分片的尾部放 mCRC——标准对校验值做了区分性处理（校验值末 16 位取反），使它不可能等于任何合法整帧的 FCS；最后一个分片才放原帧真正的 FCS（不取反）。
  • 于是接收端算完校验就知道："校验像 mCRC → 这是分片，后面还有，继续等"；"校验是完整 FCS → 整帧结束，重组完成，交上层"。
  • 为什么不用"等超时"来判断？因为超时值是不确定的，会引入不确定时延——而车载网络要的就是确定性。

③ 为什么必须先"报备 + 验货"：

  • 帧抢占改变了链路上的帧格式（前导码 + CRC 都动了）。如果对端是老设备，它不认识 SMD，也不会按 mCRC 判断——会把这些分片全部当成坏帧丢弃，整条链路直接报废。
  • 所以 802.3br 要求链路两端先做能力确认（verify / respond 握手，配合 LLDP 宣告"我支持帧抢占"）：双方都确认支持并配置一致，才真正开启。
  • 反过来说：帧抢占是"逐链路"的开关。一条链路上只要有一头不支持，这段就退回"保护带"的传统方案；它绝不会"整车一开就自动全都有"。

结论： 前导码里的 SMD 说"我是什么身份"，尾部的 mCRC / FCS 说"后面还有没有"；因为改了格式，所以链路两端必须先互相验明身份——不认识这套暗号的对端，会把分片当垃圾扔掉。

Q3（进阶）：帧抢占和 Qav、PSFP、MACsec 分别位于哪里、管什么事？为什么它和 Qav"互不替代"？关键流错配到 pMAC 会怎样？

核心思路：四者位置不同（入口 / 出口 / MAC 内 / MAC 之上）、管的事不同；Qav 管"能不能开始发"，帧抢占管"已经在发的时候能不能被插队"；映射配错 = 关键帧自己也变成被抢对象。

① 各自的位置与职责：

机制位置管的事
Qav 信用整形交换机出口队列按流量类别控制平均速率与突发：信用攒够了才允许开始发送一个帧
PSFP（L53）交换机入口按每一条流过滤（白名单 / 最大帧长）、门控（时间窗）、限速（令牌桶）——管"这帧有没有资格进场"
帧抢占（本课）交换机出口的 MAC 内部（MAC Merge 子层）把正在发的普通帧切片让路，让关键帧插缝通过——管"已经在发的帧要不要让路"
MACsec（L52）MAC 之上，加密整个帧并追加 ICV管"这条链路上的数据是不是真的、有没有被改或重放"——内容信任

② 为什么帧抢占和 Qav"互不替代"：

  • Qav 的决策点只在"一个帧要不要开始发送"这一刻：信用余额够，才放它上路。
  • 但帧一旦上路，Qav 就管不了它了——以太网不允许中途打断。所以一个已经开始的 1500 字节帧，会照样占满链路一段时间。
  • 帧抢占恰恰补的就是这个缺口：它管的是"已经在路上的帧能不能被暂时叫停"。Qav 决定"谁能上路"，帧抢占决定"上路后遇到救护车谁靠边"。
  • 两者可以叠加使用：先被 Qav 整形（控制平均速率、平滑突发），再在需要时被 Qbu 抢占（给关键帧让路）。

③ 关键流错配到 pMAC 会发生什么：

  • pMAC 是被抢的一侧。把关键队列映射到 pMAC，等于关键帧自己成了"被抢对象"——它既不能打断普通帧，还会在遇到别的 eMAC 帧时被切开、被推迟。
  • 后果：关键帧的时延不再确定，最坏时延可能回到"被大帧挡住"的原点——Qbv 给了它时间窗，但因为判断错了它"该走哪个 MAC"，抢占机制形同虚设。
  • 还有一种常见情况：链路上某一跳不支持帧抢占或未启用。帧抢占是逐跳协商的，那一跳就会退回保护带方案，端到端时延预算照样被破坏——只是这一段由那台设备决定。
  • 因此工程上要做两件事：配置后抓包验证关键帧确实走了 eMAC（独占、不被切）；逐跳清点设备能力并写进配置基线，别假设"配了整车就有"。

结论： Qav 管"能不能上路"、帧抢占管"上路后能不能被叫停"、PSFP 管"能不能进场"、MACsec 管"内容可不可信"——四道关各在一处，谁也代替不了谁；而只要映射或链路能力有一处配错，帧抢占就会"配了等于没配"。

选择题答案

MCQ1：带宽被"吃掉"一块、周期压不下去，原因与帧抢占的改善？

✅ B. 时间窗切换前必须留保护带，其长度等于发一个最大帧的时间（约 123 µs），这段时间不能开始发新帧；帧抢占允许把正在传的普通帧切开、让关键帧插缝通过，保护带只需按最小分片留（64 + 63 = 127 字节，约 10 µs），带宽浪费大幅下降

解析：保护带是 Qbv 的固有代价——因为帧一旦开始发送就不能被打断，只能用"发送最大帧（1542 字节）的时间"当保护带，100 Mbps 下约 123 µs，这段时间完全不能发新帧。帧抢占允许把正在传的普通帧切开，让关键帧插缝通过，保护带只需覆盖"最小分片 + 尚未切走的余量" = 64 + 63 = 127 字节（约 10 µs），节省 90% 以上。A 错：VLAN 标签只占 4 字节，与"整段空档"无关；C 错：MACsec 的 ICV 开销是帧长问题，不是保护带问题；D 错：保护带限制的是"能不能开始发新帧"，与 PSFP 令牌桶无关，提高令牌桶速率也不会消除保护带。

MCQ2：关于帧抢占的"分片与重组"，哪项描述正确？

✅ B. 帧抢占是逐跳行为：每条链路各自把普通帧切成至少 64 字节的分片，下一跳（交换机）立刻重组为完整帧；被抢的帧可被多次抢占；非末分片用 mCRC、末分片用原帧 FCS，接收端据此分辨分片与整帧

解析：帧抢占与 IP 分片的关键区别就在这里——它是逐跳（link-by-link）的：一头切、相邻一跳立刻重组，交给交换机时已是完整帧；同一帧可以被连续抢占多次。分片的最小长度是 64 字节（非末分片），这也是残余保护带 127 字节的由来。A 错：这是 IP 分片的模型（端到端重组），不是帧抢占；C 错：分片不能任意小——非末分片至少 64 字节，否则接收端难以可靠识别、也会让开销失去意义；D 错：重组由相邻链路的 MAC Merge 子层完成，是交换机 / 端节点硬件的活儿，不是上层协议的事。

MCQ3：哪种情况最可能导致"帧抢占配了却没效果"？

✅ A. 关键流的队列被错配到了 pMAC（或该队列未启用抢占相关配置），于是关键帧自己也成了"被抢对象"，不会去打断普通帧；同时链路上只要有一跳不支持，保护带方案也会退回——功能是逐跳协商启用的，任一跳缺失即在该跳失效

解析：帧抢占生效依靠两件事：一是802.1Qbu 的队列到 MAC 映射——只有映射到 eMAC 的队列才有"抢别人"的权利，映射到 pMAC 的只能"被抢"；二是逐跳的链路能力协商——802.3br 改了前导码与 CRC，任何一跳不认识这套格式就只能退回保护带。两者任一不满足，功能就形同虚设。B 错：芯片型号相同只是前提，映射、门控、链路易用性都要配置和协商；C 错：帧抢占不是全车一开就全有，恰恰是逐跳逐链路启用；D 错：它依赖的是链路两端的 MAC 能力与协商，gPTP 时钟不是帧抢占的前提（时钟是 Qbv 时间窗的前提）。
