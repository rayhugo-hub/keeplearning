一、先想想这个场景：为了"准点"，居然要空出 123 微秒

L47 讲过 Qbv（时间感知整形）：交换机出口被切成一段段"时间窗"，关键流（转向、制动、智驾）有专属窗口，普通流（视频、OTA、日志）在别的窗口发。

但以太网有一条铁律：一个帧一旦开始发送，就必须发完——前导码、数据、CRC 校验，谁都不能中途打断它。

于是问题来了：在普通流时段的最后时刻，一个 1500 字节的大帧开始发送。它刚好跨过时间窗边界，撞进下一个关键流窗口——关键帧被迫多等"这个大帧发完的时间"。而车载关键控制流的时延预算常常就是几百微秒级别，这一下就可能超预算。

Qbv 的标准解法是保护带（Guard Band）：在关键窗口前留出一段"谁都不许开始发新帧"的时间。留多长？必须等于发一个最大帧所需的时间：

1500（载荷）+ 18（地址/类型/CRC）+ 4（VLAN 标签）+ 12（帧间隙）+ 8（前导码）= 1542 字节，在 100 Mbps 链路上约 123.36 µs。

flowchart LR A["✅ 普通时段：开始发 1500 字节大帧"] --> B["🚧 保护带：约 123 µs 内禁止开始发新帧"] B --> C["⭐ 关键时段：转向 / 制动帧准点发出"]

代价非常直接：每个周期、每个关键窗口前都要牺牲约 123 µs 的带宽。100 Mbps 链路总共只有每秒 1250 万字节的容量，这 123 µs 相当于每次白扔约 1.5 KB。周期越短、关键窗口越多，浪费越大——而且周期时间根本压不下去。

类比：高速公路上要让救护车随时能插进来，就得在它前面留一段"空档"。如果空档必须按"最长的大货车（1500 字节）"来留，那普通车流的通行效率就很低。

能不能让大车先靠边停在应急车道，等救护车过去再接着开？这就是帧抢占（Frame Preemption）：把正在传的普通帧切开，让关键帧插在切缝里先走，之后再把普通帧剩下的部分接着传完。

二、一个概念：把"慢车"切成段，让"快车"插缝过

帧抢占由两份标准合力定义，分工清清楚楚：

标准管什么归属
IEEE 802.1Qbu桥的管理部分：哪些帧可以被抢、哪些帧可以抢别人（队列到 MAC 的映射、配置与状态）IEEE 802.1（交换机 / 桥的视角）
IEEE 802.3br（IET，Interspersing Express Traffic）MAC 部分：怎么切、怎么拼（前导码改写、CRC 规则、链路能力握手）IEEE 802.3（以太网 MAC 的视角）

效果：保护带不再需要按"最大帧 1542 字节"留，只需要按"最小可抢分片"留——

  • 802.3br 规定非末分片的最小长度为 64 字节（这也是最小合法以太网帧的尺寸）；
  • 硬件在 64 字节粒度上检查"要不要让路"，最坏情况下最多有 63 字节已经发出、来不及切；
  • 于是残余保护带 = 64 + 63 = 127 字节。100 Mbps 下仅约 10.2 µs，比原来的 123 µs 缩短了 90% 以上。
flowchart LR P1["🚚 普通帧（1500 字节）已发出 512 字节"] --> E1["⭐ 关键帧整帧插缝通过（快车不会被切）"] --> P2["🚚 普通帧续发剩余 988 字节（还能再被抢）"]

三个必须记住的要点：

  • 抢占只发生在"逐跳"（link-by-link），不是端到端。这和 IP 分片完全不同：IP 分片是端到端的事，收端才重组；帧抢占是每条链路各自切、下一跳立刻重组，交给交换机时已经是一个完整帧了。
  • 一帧可以被抢多次。普通帧在传输过程中能被一次又一次打断，直到发完。
  • 必须两端都支持。链路这头切了，那头认不出来，帧就成了垃圾——所以链路上要先"报备 + 验货"（见下一节）。

三、切与拼的暗号：eMAC / pMAC / MAC Merge

抢占能在同一条物理链路上"插队"，靠的是在出口端口上虚拟出两个 MAC 服务，外加一个"切片 / 拼装车间"：

flowchart TB Q["出口队列组<br>（Qbv 按队列开关 · Qav 信用整形）"] --> MAP["队列 → MAC 映射表（802.1Qbu）"] MAP --> EM["eMAC（express）：关键流<br>可抢占别人，自己绝不被打断"] MAP --> PM["pMAC（preemptable）：普通流<br>可被抢占，可被切成多片"] EM --> MM["MAC Merge 子层：发送时切片 · 接收时重组"] PM --> MM MM --> PHY["PHY → 链路 → 下一跳（在下一跳重组）"]
  • eMAC（express MAC，快车）：走关键流的 MAC。它发的帧永不被打断，而且它有权打断别人。
  • pMAC（preemptable MAC，慢车）：走普通流的 MAC。它发的帧可以被切开，切下来的分片等 eMAC 忙完再续传。
  • 谁能抢谁、谁不能抢，由 802.1Qbu 的"队列 → MAC 映射"决定：某个优先级队列被配置成映射到 eMAC，它才有抢占权；映射到 pMAC 的，就是被抢对象。映射配错，关键流照样被抢——这是工程上最常见的翻车点。
  • MAC Merge 子层：夹在两个 MAC 与 PHY 之间，负责"切 + 拼"。发送方向把 pMAC 的帧切片并保存上下文；接收方向按顺序把分片拼回完整帧，再交给上层 MAC。因为它只跟相邻一跳打交道，所以每一跳都要有它。

分片的"暗号"：前导码和 CRC 都被改了

要让接收端知道"这半截是分片、后面还有"，标准改了两处标志位：

位置普通以太网帧抢占之后
前导码第 8 字节（原 SFD）0xD5（SFD，帧开始）SMD（Start of mPacket Delimiter）：SMD-E 快车整帧 · SMD-S 分片开头 · SMD-C 后续分片 · 另有 SMD-V / SMD-R 专供链路握手校验
尾部校验FCS（CRC-32，对整帧计算）非末分片：mCRC（按标准做了区分性处理——校验值末 16 位取反，使它区别于任何合法整帧的 FCS）；末分片：原帧的 FCS（不取反）

接收端一算 CRC 残差就知道"这是分片、后面还有"还是"整帧到此结束"——不需要靠超时去猜。这一点很关键：靠"等超时"判断会引入不确定时延，而车载网络最怕的恰恰是不确定。

链路必须先"验货"再启用

既然前导码和 CRC 都被改了，对端如果不支持帧抢占，只会把这些分片当成坏帧全丢掉。所以 802.3br 要求链路两端先做能力确认（verify / respond 握手，配合 LLDP 宣告），双方都支持才真正开启；任何一头不支持，这条链路就退回"保护带"传统方案。帧抢占是逐链路的开关，不是整车一开就全都有。

四、它和 L47 / L49 / L52 / L53 那些机制怎么配合

机制管什么与帧抢占的关系
Qbv 门控（L47）出口队列按时间表开关最佳搭档：帧抢占是 Qbv 的"减负器"——保护带从"最大帧"缩到"最小分片"，周期可以更短、带宽利用率更高。Qbv 负责"排时刻表"，Qbu 保证时刻表不被大帧越界破坏
Qav 信用整形（L47）按类控制平均速率与突发互不替代：Qav 只管"能不能开始发"，它无法中断已经在发的帧；帧抢占专治这个。两者可以叠加——先被 Qav 整形，再被 Qbu 抢占
PSFP 入口监管（L53）入口按每流过滤 / 门控 / 限速位置互补：PSFP 在入口管"这帧有没有资格进场"；帧抢占在出口管"这帧要不要给关键帧让路"。一个管资格，一个管让路
MACsec 链路安全（L52）MAC 之上加密整帧、追加 ICV层级不同：帧抢占在 MAC 内部"切 / 拼"，对 MACsec 是透明的——先按 L52 加好密，再在链路上切片传输、下一跳重组，重组完才交给 MACsec 校验解密。顺序是"先安全、后切片"，但这也意味着每一跳都要成套的硬件支持，复杂度与时延都要付代价

把 L47~L54 串一遍（一帧摄像头数据的旅程）：PHY（L48）把比特送上线 → MACsec（L52）上锁 → 交换机按 L49 的规则认流、在入口做 L53 的 PSFP 设卡 → 转发引擎查表送往出口 → 出口先按 L47 的 Qav 整形、Qbv 看时刻表；此刻若有关键帧要发，帧抢占（L54）把普通帧按 64 字节粒度切成片让路，关键帧插缝先走 → 冗余路径上用 L50 的 FRER 双发去重。帧抢占就是这条流水线上的"应急车道"。

五、工程要点

  1. 映射必须配对：只有映射到 eMAC 的队列才有抢占权。把"关键流"的优先级错配到 pMAC，等于白配置——配完一定要用抓包工具确认关键帧真的走了 eMAC。
  2. 逐跳都要支持、都要协商：任何一跳不支持，这段链路就退回保护带。做网络设计时要逐跳清点交换机 / 端节点的芯片能力，并把"是否启用"写进配置基线。
  3. 残余保护带 = 127 字节：64 字节最小分片 + 63 字节不可预判的余量。链路预算与周期计算要按这个数（而不是 1542 字节）来算——这是帧抢占最大的收益来源。
  4. 分片不是越小越好：每一片都要付前导码 / mCRC 的额外开销，切得越碎、开销越大；切得越粗，残余保护带越长。分片尺寸是"开销 vs 时延"的折中，通常由硬件按 64 字节粒度自动决定。
  5. 被抢占的帧要在下一跳"等"：重组需要缓冲，等待期间占用对方交换机的内存；关键流量越大、抢占越频繁，普通流的抖动越大。所以关键流的门控窗口要给足，否则频繁抢占反而伤害普通业务。
  6. 产业现状要清醒：帧抢占比 Qbv / Qav 实现难度高得多（要在 MAC 里保存并切换发送上下文），早期一度被认为"难以落地"；近年在车用以太网（IEEE 802.1DG profile）与车规 TSN 交换芯片上逐步可配（Microchip、NXP 等厂商的 TSN 交换机应用笔记中都有专章）。设计时先确认芯片与软件栈真的支持，再把它写进方案。

六、三条铁律（记住这三句）

  1. 它治的是"保护带太贵"：以太网帧一开头发就不能停，Qbv 只能用"最大帧时间"当保护带（100 Mbps 下约 123 µs）。帧抢占把普通帧切成最小 64 字节的分片，让关键帧插缝先走，保护带缩到 127 字节（约 10 µs）。
  2. 两个 MAC + 一个合并子层：出口端口虚拟出 eMAC（快车，不可被打断、能抢别人） 与 pMAC（慢车，可被切、可被多次抢），由 MAC Merge 子层负责切片与重组；逐跳生效、下一跳立刻重组，不是 IP 那种端到端分片。分片靠前导码 SMD 与 mCRC / FCS 两种暗号区分，链路两端必须协商验证后才启用。
  3. 它是 Qbv 的搭子，不是替代品：Qbv 排时刻表、Qbu 保证时刻表不被大帧越界；Qav 管不了"已在发的帧"，帧抢占专治这个；PSFP（L53）管入口资格、帧抢占管出口让路。关键流的队列必须正确映射到 eMAC，否则一切白搭。
