一、先想想这个场景

一辆舱驾一体车上，同一根以太网线里跑着这些流量：

  • 智驾摄像头流：每秒产生 几 GB 视频数据；
  • 底盘控制报文：必须 1ms 内从传感器传到执行器；
  • 语音助手：人耳对延迟极敏感，超过 100ms 就觉得卡；
  • 娱乐视频 + OTA 下载包：永远在抢带宽。

普通以太网的态度是："尽力而为"（best-effort）——数据到了交换机就排队，谁排到谁先走，堵车时大家一起等。

于是问题来了：

  • 摄像头大流量把交换机缓存塞满，底盘控制报文会不会迟到？
  • 视频下载把带宽占完，语音会不会卡顿？
  • 最要命的是：迟到的延迟是多长时间，没人说得准——100ms 还是 1s？
这一课讲清楚：TSN（Time-Sensitive Networking，时间敏感网络）给普通以太网装上"同步时钟 + 红绿灯 + 专用车道"，让关键报文延迟可预测、有上界——说好 1ms 到，就一定能 1ms 到。

二、为什么普通以太网"不准时"？

1. 以太网的"尽力而为"基因

以太网诞生于办公网络：共享线缆、谁想发就发（CSMA/CD），后来变成交换机 + 缓存队列。它的设计目标是"别丢数据"，从来没承诺过"多久能到"。

2. 延迟来自哪里？

环节造成什么延迟是否可控
排队延迟报文进交换机缓存队列，前面有大流量就得等❌ 最不可控
转发延迟交换机查表、转发（存储转发要收完整帧）✅ 固定
链路延迟电信号在线上跑✅ 固定（~5ns/m）
串行化延迟帧一位一位发出去要时间✅ 与速率相关

关键：排队延迟是"变量"——普通流量一多，关键报文排队时间暴涨，而且无法预测。

3. 车载场景为什么忍不了？

  • 底盘控制：延迟 10ms 以上 → 车辆动态变差；
  • ADAS 融合：摄像头流延迟抖动 → 目标位置错位；
  • 音频：延迟抖动 → 爆音、卡顿。
结论：普通以太网"大概率能到，但说不准什么时候到"。汽车要的是"一定能到，且说好几点到就几点到"。TSN 就是干这个的。

三、TSN 是什么：一组让以太网"准时"的标准

TSN 不是一项技术，而是一整套 IEEE 802.1 标准族，目标：在标准以太网上，为关键流量提供有界的延迟、极低的抖动、零丢包。

三块基石：

基石标准一句话作用类比
① 时间同步802.1AS（gPTP）全网节点共用一个"手表"，精度亚微秒高铁调度中心统一时间
② 调度整形802.1Qbv / Qav / Qbu给关键流量"定时放行 + 专用通道"红绿灯 + 专用车道 + 应急车道
③ 流预留802.1Qcc / Qat发车前先"订票"，预留带宽高铁订票，保证有位

四、基石一：时间同步（802.1AS gPTP）

1. 为什么必须先同步时间？

Qbv 的"时间窗"、时间戳测量、多传感器融合——全都依赖全网节点对"现在几点"有一致的认识。各走各的表，时间窗就会错位。

2. gPTP 怎么同步？

  • 全网选一个 Grandmaster（主时钟）——通常是最准的那个节点（如带 GNSS 授时的域控）；
  • 主时钟逐跳向下分发时间：交换机 A 收到"现在 10:00:00.000000100"，算出链路延迟，校准自己的时钟；
  • 报文携带 精确时间戳，接收方知道"这帧是什么时候发的"。

3. 精度有多高？

gPTP 在网桥逐跳同步后，端到端时钟偏差可做到 百纳秒级（<1μs）——比普通 NTP（毫秒级）精确几千倍。

五、基石二：调度整形（Qbv / Qav / Qbu）

这是 TSN 的核心——用三种手段让流量"分时错峰"。

1. Qbv：时间感知整形（Time-Aware Shaper）——"红绿灯"

  • 每个端口配一张 门控列表（GCL, Gate Control List），像一个循环播放的节目表；
  • 时间窗内：只有关键流量开门放行，普通流量全被"红灯"拦住；
  • 周期循环：关键窗 → 普通窗 → 关键窗……
flowchart LR W1["时间窗 1：关键流量<br>（底盘控制，开门 100μs）"] W2["时间窗 2：普通流量<br>（视频/OTA，开门 900μs）"] W3["时间窗 3：音频流<br>（语音，开门 50μs）"] W1 -- 周期循环 --> W2 -- 周期循环 --> W3 -. 回到起点 .-> W1

效果：关键报文的时间窗固定，永远不会被普通流量挤掉——延迟有上界，抖动趋近于零。

2. Qav：信用整形（Credit-Based Shaper）——"限速器"

  • 普通流量（音视频流）有个"信用额度"，发一帧扣一点，额度用完就闭嘴等；
  • 效果：AVB 音视频流不会一次爆发把交换机缓存塞爆，保证平滑。

3. Qbu：帧抢占（Frame Preemption）——"应急车道"

  • 普通大帧（如 1500 字节的视频帧）发送途中，紧急小帧可以插队；
  • 大帧先暂停，让小帧先过，再续传——物理层支持（802.3br）；
  • 效果：关键小报文不用等大帧发完，延迟再降一级。
整形器管什么流量手段类比
Qbv时间关键流（控制、同步）固定时间窗放行红绿灯定时放行
QavAVB 音视频流信用额度限速限速器 / 单双号限行
Qbu紧急小报文 vs 普通大帧大帧让路应急车道插队

六、基石三：流预留（802.1Qcc / Qat）——"订票制"

  • 关键数据流发送前，先向网络申请预留：路径、带宽、延迟要求；
  • 交换机逐跳确认"我能保证"后，签署承诺；
  • 预留成功后，这条流端到端延迟有合同保证。

类比：高铁订票——出发前确认有座，上车才不慌；普通流量是"站票"，有位就坐，没位站着。

一句话总结： TSN = 标准以太网 + 全网同步时钟（AS）+ 定时放行（Qbv）+ 限速（Qav）+ 插队（Qbu）+ 订票（Qcc）——让关键流量延迟可证明、有上界。

八、三条铁律（记住这三句）

  1. TSN 不是提速，是"确定性"——它不让网络更快，而是让关键流量的延迟可预测、有上界、零丢包。
  2. 时间同步是一切的地基——没有 802.1AS 的亚微秒级同步，Qbv 时间窗、时间戳、融合算法全都会错位。
  3. 分工明确：Qbv 定时放行（红绿灯）、Qav 限速（限速器）、Qbu 插队（应急车道）、Qcc 订票（高铁票）——各管一类流量，组合起来保证关键报文准点到。
