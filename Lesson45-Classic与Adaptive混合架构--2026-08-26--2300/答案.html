Classic 与 Adaptive 混合架构——一辆车里为什么有"两个 AUTOSAR"？

← 上一课 ☰ 目录 📖 返回课程

费曼简答题参考答案

Q1：为什么一辆车里要同时存在 Classic 和 Adaptive 两套平台？

平台类比不可替代的原因
Classic（CP）铁路调度室：时刻表提前排好，绝不临时改点安全关键功能（制动、转向、气囊）需要确定性——"什么时候跑、跑多久、用多少资源"在编译期定死、可验证、可证明，这是 ASIL-D 认证的基本要求；静态配置 + 实时 OS 保证毫秒级可预期响应
Adaptive（AP）网约车平台：乘客随时下单、车辆动态调配智驾/座舱负载动态变化（算法版本升级、App 增减、OTA），需要动态部署、服务发现、大算力与 POSIX 生态；强确定性会牺牲灵活性，无法承载复杂算法
结论：一辆车既有"必须可证明的安全功能"，又有"必须灵活迭代的智能功能"——两套平台各管一摊，不是替代关系，是分工关系。统一成一套会两头不讨好：让 CP 变"活"会失去确定性，让 AP 变"死"会失去灵活性。加分：说清"信号级静态通信 vs 服务级动态通信"、"确定性/可认证 vs 算力/生态"的核心矛盾，并点出两者需要"跨域对话"（引出网关/S2S）。

Q2："服务型网关"在 CP 和 AP 之间做了什么？

  • 为什么需要：CP 世界说"信号语"（CAN 报文 0x123 第 0 字节低 8 位是车速，分辨率 0.01 km/h），AP 世界说"服务语"（Vehicle.Speed 接口一调用返回浮点数）——语言不通，直接对话会鸡同鸭讲，中间必须有"翻译官"。
  • 三件事：
    • 协议转换：CAN/LIN ↔ 以太网（SOME/IP）——把"电报"换成"电话线路"；
    • 语义翻译：原始信号值 → 服务接口（单位换算、打包/解包）——把"摩尔斯电码"译成"普通话"；
    • 路由与安全：跨域转发、访问控制、限流防攻击——海关+邮局，检查包裹再放行。
加分："翻译"不是简单转发——同样的车速，CP 侧是 16 位原始值，AP 侧是带单位的浮点数，网关要做语义级转换，还要保证实时性（低延迟转发）与安全性（不能把攻击报文放进安全域）。

Q3：S2S 通信解决了什么问题？

  • 解决的问题：让 CP 的 SWC（软件组件）也能以"服务"身份参与 AP 的世界——CP 侧把 Port 暴露成服务（S2S 模块 + RTE 扩展），AP 侧用 ara::com 像调用本地服务一样调用，CP 的 SWC 既能当服务提供者、也能当服务消费者。
  • 21-11 之前为什么麻烦：
    • 没有统一标准，每家 OEM 自己写专有网关桥接代码——重复造轮子、不可复用、难维护；
    • 跨供应商/跨车型集成时接口五花八门，联调成本高；
    • 信号↔服务的转换逻辑散落在各项目里，质量参差不齐。
  • 标准化之后：统一接口、跨 OEM/供应商复用、降低集成成本——S2S 成了 CP 与 AP 之间的"官方语言"。
加分：能说出"服务型网关负责翻译、S2S 负责定标准，两者配合"的层次关系，并联系上一课（S2S 依托 SOME/IP 等服务传输协议在以太网上跑）。

选择题参考答案

MCQ1：哪一项最准确地概括了 CP 与 AP 的核心区别？

✅ A. CP 面向安全关键 ECU、信号级静态通信；AP 面向高性能计算、服务级动态通信
解析：CP 以信号（Signal）为通信粒度、编译期静态配置，追求确定性与可认证；AP 以服务（Service）为粒度、运行时动态发现与部署，追求算力与灵活性。B 太绝对（Hypervisor 下 AP 平台也能承载 CP 虚拟机，反之 CP 概念不依赖具体芯片）；C 说反了（CP 诞生于 2003 年更早）；D 完全错误。

MCQ2：制动冗余控制（ASIL-D）应该部署在哪个平台？

✅ B. 部署在 CP 平台，因为静态配置、确定性好、可认证
解析：ASIL-D 要求执行时间与资源可用性可证明，CP 的静态配置 + 实时 OS 正是为此设计；AP 算力强但动态调度带来不确定性，不适合"救命功能"。云端延迟不可控，绝不可用于制动控制。

MCQ3：关于 S2S 通信，下列说法正确的是？

✅ A. S2S 让 CP 的 SWC 也能作为服务提供者/消费者与 AP 应用通信，AUTOSAR 21-11 标准化
解析：S2S（Service-to-Service）是 AUTOSAR 21-11 正式标准化的 CP ↔ AP 服务通信机制，把 CP 的 SWC Port 暴露为服务，AP 用 ara::com 调用。B 错（S2S 是应用层通信机制，不是物理层总线）；C 错（S2S 恰恰是跨 CP/AP 的，不是 AP 内部）；D 错（S2S 通常承载于 SOME/IP 等传输协议之上）。
