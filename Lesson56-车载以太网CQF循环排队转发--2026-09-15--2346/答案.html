车载以太网 CQF 循环排队转发——两个队列轮流"当班"，时延抖动凭什么涨不上去？

费曼简答题参考答案

Q1：用"两个班次轮流值班"打比方：三条硬规则是什么？为什么一帧最多等两个周期？为什么不允许"本周期到本周期发"？为什么"每跳推后一个节拍"不会让波动累积？

核心思路： 三条规则（只进等待席 / 周期换岗 / 必须等一个节拍）把"连续流"切成"批次"；批次的编号只加不放大，所以上界只跟跳数有关。

① 打比方：两个候车区的车站

  • 把每一跳想象成一个只有两个候车区的车站：一个叫 等待区，一个叫 发车区。每隔固定的节拍长度 T，车站把两个区互换一次。
  • 原来在等待区的那一批乘客，整批转移到发车区，立刻出发；同时新来的乘客只能进新的等待区。
  • 所以任何乘客到站后都至少要待满一个节拍——因为它到站时只能进等待区，本班车绝不允许它上。

② 为什么最多等两个周期（每跳停留 ≤ 2T）

等待项最坏原因
等换岗T帧只能写进等待席，必须等下一个周期边界
等前面发完T换到当班席后，它排在那一批里其他帧后面
合计≤ 2T最快几乎 0（恰在换岗前一刻到达、且当班队列为空），最坏 2T

③ 为什么"本周期到本周期发"是不允许的

  • 如果允许，同一个节拍里早到的帧就会插队在晚到的帧前面——谁先谁后完全取决于到达时刻的微小差别；下一跳这种差别会继续放大，时延又变得不可预测。
  • 这正是普通 FIFO / CBS 的老毛病。强制等一个节拍之后，同一个节拍内到达的所有帧被打包成同一批，一起在下一个节拍出发——先后关系被彻底抹掉了。

④ 为什么波动不会越走越大

  • 因为全网的节拍是同一相位、换岗时刻全网对齐：帧在节拍 n 到达第一跳 → 一定在节拍 n+1 离开第一跳；到达第二跳时正好落在节拍 n+1 里 → 在节拍 n+2 离开第二跳；每过一跳，出发的节拍号只 +1。
  • 也就是说，每一跳转移的只是批次编号，批次的先后与间隔既不会被拉大、也不会被压缩——没有累积误差。
  • 所以 3 跳的端到端上界就是 4 个节拍 = (H+1)×T，而且这个上界与网上有多少条流无关。

Q2：周期 T 为什么不能随便取？T 太小的两件坏事、T 太大的代价？为什么上界"与流数无关却与跳数有关"？为什么"不超容量"必须靠入口监管来守？

核心思路： 节拍长度是唯一旋钮：太小装不下（模型失效 / 上界失效），太大时延线性增长；而那条漂亮性质全靠"每周期不超容量"这条红线撑着。

① T 太小的第一件坏事：连一帧都发不完

  • T 必须大于最大帧的发送时间。以 100 Mbps 链路为例，1500 字节的帧要 120 µs：若 T 只取 100 µs，一个节拍连一个最大帧都发不完，帧会横跨两个节拍，等待席 / 当班席这套模型直接失效。

② T 太小的第二件坏事：装不下，余量滚到下一周期

  • 每个节拍能发出去的字节数是固定的：每周期容量 = 端口速率 × T。
  • 100 Mbps = 12.5 MB/s → T = 100 µs 时每周期只能发 1250 字节，连一个 1500 字节的帧都装不下；而若某类流量在一个节拍里集中到达 6000 字节（4 个 1500 B 帧），超出的部分只能滚到下一个节拍。
  • 这一滚，每跳 ≤ 2T 的停留上界和 (H+1)T 的端到端预算同时失效；缓冲不够时直接丢帧。
  • 正确做法：T 至少加大到 6000 ÷ 12.5 MB/s = 480 µs（工程上取 500 µs 以上留余量），或者降低该类的每周期到达量。

③ T 太大的代价

  • 端到端上界 (H+1)×T 随时延线性增长——T 翻一倍，时延预算翻一倍；
  • CQF 的时延是以节拍为颗粒被量化的：同一批帧不管早到晚到，都在同一个节拍出发，代价是它们都至少被推迟一个节拍。
  • 所以标准动作是：先用最坏周期的到达量反推 T 的下限，再在这个下限之上尽量取小。

④ 为什么"与流数无关，却与跳数有关"

  • 与流数无关：每过一跳，帧的出发节拍号只 +1；干扰只影响它在这个节拍里排第几，不影响它属于哪个批次。网上的流再多，只要每个节拍不超容量，它们都被装进同一批一起走。
  • 与跳数有关：跳数每加一跳，就多消耗一个节拍。所以 H 直接进入公式：上界 = (H+1)·T。

⑤ 为什么"不超容量"必须靠入口监管来守

  • 不超容量是这个性质成立的前提，而流量是活的：某条流一旦发疯，或多个类同时突发，端口侧的周期容量就会被顶穿；
  • 超出的部分只能滚到下一个节拍，上界当场失效，甚至溢出丢帧；
  • 所以必须在交换机入口按每一条流做过滤与限速（L53 PSFP），把没资格和超量的流量挡在门外或降级，再配合队列长度管理 + 丢弃策略，让每个节拍都干干净净地装得下。

Q3（进阶）：CQF / Qbv / CBS 三者对比；为什么 CQF"像 Qbv 的特化用法"却好配置得多？"以节拍量化"与"平均速率"的语义区别？超容量会怎样"失信"？

核心思路： 三者承诺的东西根本不同——一个是"时延有界"、一个是"准点"、一个只是"平均速率"；而 CQF 像是给门控用法做了一次极简特化。

① 三者的承诺与代价

机制承诺配置成本适用场景
CBS / Qav长期平均速率 ≤ 预留；突发被上限锁住（无硬时延上界）低：两条斜率 + 一道门槛，不需要全网时钟有明确码率、需要平滑、但不苛求时延上界的流（音视频类）
Qbv 门控硬时延上界（可很紧）、准点高：gPTP 全网同步 + 离线逐流算表，改网必重算控制指令等对时延 / 抖动极敏感的流
CQF / Qch（本课）每跳 ≤ 2T、端到端 ≈ (H+1)T，且与流数量无关中低：全网只要一个 T（+相位），不用逐流算表要求"时延有界 + 配置可维护"的整流（车载骨干、音视频、控制数据）

② 为什么说它"像 Qbv 的特化用法"

  • 实现方式本质相同：给两个队列各挂一个门，两个门按 50% 占空比反相开关，节拍一到就换边——这正是门控时间表的一个固定样式；
  • 区别在于"要不要逐流定制"：Qbv 要为每条流算出精确的开关时刻；CQF 不需要为任何一条流定制，全网只要一个节拍长度（+相位对齐）；
  • 于是配置成本从天花板降到地板，代价是上界变松——因为时延被量化到节拍的整数倍附近。

③ 与"平均速率"承诺的语义区别

CBS（速率语义）CQF（时刻语义）
承诺什么长期平均速率 ≤ idleSlope某一帧最晚在第几个节拍走
关心单帧时刻吗不关心只关心时刻
关心速率平滑吗关心（防突发）不承诺平滑，只要求每节拍不超容量
结论管"流量"管"时刻"

语义完全不同，所以同一队列上通常只选一个。

④ 怎么"失信"

  • 前提是每周期不超容量。某类流量若在一个节拍里灌进来的比端口一个节拍能发出去的多，多出来的帧就发不完；
  • 只能滚到下一个节拍，甚至侵占下一批的时间 → 每跳 ≤ 2T 的上界与 (H+1)T 的端到端预算同时被打破；
  • 缓冲也不够时帧被丢弃。所以必须用入口监管 + 队列长度 + 丢弃策略守住红线，否则写在纸上的时延保证就是一纸空文。

⑤ 冗余路径要注意

  • 两条冗余路径（FRER，L50）的节拍与相位必须一致；否则去重时要靠放大窗口去容忍两侧时延差——等于把冗余换来的时延预算又送回去。

结论： CQF 用"双缓冲 + 固定节拍"把时延从"没有保证"变成"(H+1)T 有保证、且与流数无关"，代价是节拍量化带来的平均时延、全网相位对齐要求、以及必须守住每周期不超容量的红线。

选择题答案

MCQ1：CQF（IEEE 802.1Qch）的核心机制，哪项描述正确？

✅ B. 每个出端口准备成对的两个队列（等待席 / 当班席），按固定周期 T 交换角色；本周期到达的帧只写入"等待席"，由另一个队列整批转发，因此一帧最快在下一个周期被发出，每跳停留不超过 2T

解析：B 正确——这就是 CQF 的全部机制：双缓冲 + 固定节拍 + 强制等一个周期。由此推出"每跳停留 ≤ 2T"（等换岗 T + 等前面发完 T），并配合全网相位对齐推出端到端上界 ≈ (H+1)T。A 错：那是 CBS / Qav（信用整形）的描述——单队列 + 信用余额门槛；CQF 靠的是队列角色交替，不是信用额度。C 错：为每条流离线算时刻表是 Qbv 的做法；CQF 的魅力恰在于不需要逐流算表，只要全网一个 T。D 错：CQF 要求全网周期与相位对齐（依赖 gPTP / 802.1AS）；各跳周期任意错开的话，"每跳只把周期号 +1"这个推理不成立，上界也就没了。

MCQ2：100 Mbps 链路、T = 100 µs，某类每周期集中到达 6000 字节，平均需求仅约 12 Mbps；结果帧被推迟到再下一个周期、时延超标、个别丢帧——原因与正确做法？

✅ B. 每周期容量 = 端口速率 × T = 12.5 MB/s × 100 µs = 1250 字节，连一个 1500 字节帧都装不下，而该类一个周期要发 6000 字节 → 余量被滚到下一周期、上界失效。应把 T 至少加大到 6000 ÷ 12.5 MB/s = 480 µs（工程上取 500 µs 以上留余量），或降低该类每周期到达量

解析：关键算式——100 Mbps = 12.5 MB/s；每周期容量 = 12.5 MB/s × 100 µs = 1250 字节。1250 字节 < 1500 字节，连一个最大帧都装不下（仅这一条就已判了 T = 100 µs 的死刑）；而该类一个周期要发 6000 字节，容量缺口近 5 倍。现象与病因完全对上：装不下的部分滚到下一个节拍 → 帧被推迟、(H+1)T 预算失效、缓冲不够时丢帧。T 的下限 = 6000 ÷ 12.5 MB/s = 480 µs → 工程上取 500 µs 以上。A 错：CQF 的 T 通常在 µs 到 ms 量级（车载常用 100 µs ~ 1 ms），1 秒完全脱离工程现实。C 错：帧抢占（L54）管的是"正在发送的帧要不要让路"，与 CQF 的周期切换是否生效毫无关系。D 错：CQF 不依赖 CBS；两者是"同一队列上二选一"的关系（一个管时刻、一个管速率），缺 CBS 不会让 CQF 失效。

MCQ3：关于 CQF 的时延特性与配置代价，哪项最准确？

✅ A. CQF 的端到端时延上界 ≈ (H+1)·T（H 为跳数），只取决于跳数与周期、与网上流数量无关；代价是 T 的量化颗粒、必须全网同周期同相位、并且必须守住"每周期不超容量"，否则上界失效

解析：A 正确——三句话把 CQF 的价值（上界与流数无关）与代价（量化颗粒 / 相位对齐 / 容量红线）说全了。B 错：上界随竞争流数量增长，是 CBS / Qav 这类"无硬保证"机制的毛病；CQF 的最大优势正好相反——只要每周期不超容量，上界与流数量无关（每跳只是把节拍号 +1）。"流多了改小 T"也错：改小 T 会降低每周期容量，反而更容易超容量。C 错：CQF 把抖动压小到节拍量级，但不是 0——不同批次之间仍有 T 的台阶，说"抖动为 0、完全确定性"是过度承诺。D 错：CQF 同样依赖时间同步（gPTP 用于对齐周期与相位）；而且它的上界是以节拍为颗粒的，比精心排布的 Qbv 时刻表更松——说"比 Qbv 更紧"完全说反了。
