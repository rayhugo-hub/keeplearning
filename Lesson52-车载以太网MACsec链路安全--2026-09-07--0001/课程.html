一、先想想这个场景

车联网安全里最难防的不是"远程黑客"，而是能碰到车的人：维修厂技师、代客泊车小哥、二手车商……只要一小段物理接触，就能做很多事：

flowchart LR GW["🚗 中央网关"] DC["🧠 智驾域控"] W["骨干网线"] T["🕵️ 偷听者<br>（并线分光 / 调试口 / 诊断口）"] GW --- W --- DC W -. "把经过的帧全部复制一份" .-> T
  • 在网关和域控之间的骨干网线上串一个分光小盒子（物理并线）；
  • 往交换机空余的调试端口插一根线；
  • 或者干脆利用本来就开放的 OBD 诊断口（L51 说过：插上就能发起 DoIP 诊断）。

问题在于：以太网帧默认是明文。摄像头拍的画面、雷达点云、SOME/IP 服务调用、DoIP 诊断/刷写指令、gPTP 校时消息……全都赤条条地在网线上跑。偷听者不仅能看，还能照着样子伪造一帧（比如伪造一条"解锁车门"的 SOME/IP 消息）发进网络。

有人会说：以太网不是交换式的吗？交换机不是会隔离吗？——交换机隔离挡的是"普通端口收不到别人的流量"，但物理接触（分光、串接）、端口镜像、开放调试口都不在它的隔离范围内。而且加密从来不是以太网的默认项。

这一课讲的就是给网线"上锁"的技术：MACsec（IEEE 802.1AE）——链路层加密，让碰得到线的人也偷不走、改不了、重放不了。

二、为什么偏偏要在"网线"这一层上锁？

先复习一下网络分层：数据从应用出发，一层层套上信封——应用层（HTTP/SOME/IP）→ 传输层（TCP/UDP）→ 网络层（IP）→ 链路层（以太网 MAC）→ 物理层（网线）。每一层都能加"锁"，但罩住的范围不一样：

方案在哪一层管得住管不住
TLS/HTTPS应用层单个 TCP 应用（如 OTA 下载、云端连接）其他应用不管；UDP/组播/广播不碰；每个应用要单独接入
IPsec网络层IP 单播报文组播/广播很别扭；非 IP 的帧根本不在视野里
SecOC（L32）报文层（端到端）报文的"身份与完整性"：防伪造、防篡改不做加密——防的是"假信"，不是"偷看"
MACsec（本课）链路层一条链路上经过的所有以太网帧只管相邻两个节点之间的这一段

为什么上层那些锁不够？看看车里"别的锁罩不住"的关键流量：

  • SOME/IP 服务发现（L39）——UDP 组播，一喊一大片，不是某个 TCP 连接；
  • gPTP 时间同步（L47）——EtherType 0x88F7，根本不是 IP 报文，IPsec 管不着；
  • 诊断功能寻址（L51）——一条消息广播给一组 ECU；
  • 摄像头/雷达视频流——海量 UDP，逐帧上 TLS 不现实。

这些流量要么没有 IP、要么是组播/广播、要么不想被应用层改造拖慢。TLS 只保护"愿意接入的单个 TCP 应用"，IPsec 对组播/广播和非 IP 帧有盲区——唯独在链路层上锁，才能不分协议、不分应用，把"凡是走这条网线的帧"统统罩住。而且 MACsec 对上层完全透明：IP 地址不用改、应用一个字节都不用改，它甚至不知道自己正被加密。

类比：TLS 像"寄件人给某几封信单独糊上蜡封"，MACsec 像"整条邮路配武装押运 + 加密车厢"——后者不挑信件，只要是这条路上的全罩住。标准依据：IEEE 802.1AE-2018。

三、一封"加密挂号信"——MACsec 帧长什么样

普通以太网帧是 目的地址 + 源地址 + (VLAN 标签) + 类型 + 载荷。MACsec 在源地址后面插入一个 SecTAG，把原来的"类型 + 载荷"整个加密，再在帧尾加一个 ICV 校验值：

flowchart LR A["信封地址（明文）<br>DA 6B · SA 6B · VLAN 4B"] --> B["SecTAG 8~16B<br>（类型 0x88E5）"] B --> C["🔒 密文<br>原来的类型 + 载荷"] C --> D["ICV 8~16B<br>防篡改校验值"]
部位内容可见吗
DA / SA目的/源 MAC 地址明文——交换机靠它送信
VLAN 标签VID + 优先级 PCP明文——L49 分流、L47 门控靠它
SecTAG"我是 MACsec 帧" + 控制位 + 包序号 PN明文——收方据此解密、查重
密文原来的类型 + 载荷（AES-GCM 加密）🔒 看不见
ICV完整性校验值明文，但伪造不了

SecTAG 内部（8 字节，带 SCI 时 16 字节）：

字段长度作用
TCI/AN1 字节标志位（是否加密、是否带 SCI）+ 关联号 AN（0~3，区分新旧钥匙）
SL1 字节短帧辅助长度
PN4 字节包序号，每发一帧 +1（XPN 扩展为 8 字节）
SCI可选 8 字节发送方标识（需要时携带）

"三防"就靠这个结构：

  • 防偷看（机密性）：载荷用 AES-GCM 加密（默认 GCM-AES-128，可配 256）。GCM 是一把钥匙同时干两件事：加密 + 生成校验值。
  • 防篡改（完整性）：收方用钥匙对密文重算校验值，和 ICV 对不上——帧在路上被改过，或钥匙不对——直接丢帧。
  • 防重放：PN 单调递增，收方维护滑动窗口：重复的、远远落后的"旧帧"一律进不了门。后面 MCQ 会考这个。

四、钥匙三层楼——CAK / MKA / SAK

加密的钥匙从哪来？MACsec 的钥匙是三层结构，分工明确：

flowchart TB CAK["🔑 CAK 长期主密钥<br>（128/256 位 · 预置或 802.1X 下发 · 极少更换）"] CAK -->|"派生"| KI["KEK：给 SAK 加密运输<br>ICK：给 MKA 消息做校验"] KI --> MKA["MKA 密钥协商协议<br>（EAPOL 0x888E · 保活 · 分发）"] MKA -->|"定期分发"| SAK1["🔑 SAK 当前数据密钥"] MKA -->|"无缝轮换"| SAK2["🔑 SAK 新密钥（新旧并存，确认切换后再废弃旧的）"] SAK1 --> ENC["📨 加密每一帧数据"] SAK2 --> ENC
钥匙干什么多久换藏在哪
CAK"总根"，派生出下面两把极少换（产线预置 / 802.1X 下发）HSM 保险柜（L32）
KEK / ICKKEK 给 SAK 加密运输；ICK 保护 MKA 消息本身随 CAK各节点
SAK真正加密每一帧数据的钥匙定期自动轮换（秒级~分钟级，实现可配）硬件加密引擎

运转流程：

  1. 用同一个 CAK 的节点组成一个"连通域"（CA，Connectivity Association）；
  2. 其中一台担任钥匙服务器（Key Server），通过 MKA（MACsec Key Agreement，跑在 EAPOL 上，EtherType 0x888E）把 SAK 发给其他节点——发送时用 KEK 把 SAK 包起来，路上没人能偷看；
  3. MKA 还负责点名保活：谁掉线了、谁被拔走了，大家马上知道，掉线的节点自动失去通信资格；
  4. 换钥匙不停机：新 SAK 先分发到位，新旧并存一小段（TCI/AN 里的 AN 0~3 四个槽位就是干这个的），确认全员都切到新钥匙后，再废弃旧的——像小区换门锁：先把新钥匙发到每家、确认都能进门，再作废旧钥匙，全程不用"停业"。

为什么不能一把钥匙用到底？ 用越久泄露风险越大；PN 只有 4 字节，高速链路很快转完一圈（所以才有 XPN 的 8 字节序号）；万一某把 SAK 真被破解，损失也被限制在它短暂的任期内。

呼应 L32：CAK/SAK 都存放在 HSM（硬件安全模块） 里——钥匙从出厂起就不离开安全芯片，软件层想偷也偷不到。

五、"一段一锁"——MACsec 是逐跳加密，不是端到端加密

MACsec 的保护范围要记牢：它只保护"相邻两个 MACsec 端点之间的这一小段网线"，帧每经过一个端点（交换机端口、网关），就要解密 → 处理 → 重新加密，再送上下一段。每一段的钥匙还不一样：

flowchart LR A["🚗 域控 A"] --- W1["段① 网线"] W1 --- G["🛡️ 中央网关<br>（可信明文点：解密 → 查表 → 重新加锁）"] G --- W2["段② 网线"] W2 --- B["📡 T-BOX"] T1["🕵️ 在段①并线偷听"] -. "只拿到密文，白搭" .-> W1 T2["🕵️ 攻破中央网关"] -. "能看到明文" .-> G
  • 段①用 SAK-A、段②用 SAK-B：一把钥匙只在一段上有效，段①的钥匙泄露不影响段②。
  • 为什么网关必须"看"明文？ 因为它是转发/翻译的节点：要读目标地址做路由、要翻译诊断（L51 的网关翻译官）、要按服务转发——它本来就必须处理内容，是设计上被信任的"明文点"。MACsec 防的是"网线上的人"，防不了"节点本身被黑"。
  • 补充一个细节：纯二层交换机只看明文的信封地址（DA/SA/VLAN）就能把密文帧送出去，不一定要解密；但只要设备要"读内容"（三层路由、SOME/IP、诊断翻译），解密就躲不掉——它也随之成为可信明文点。

那"节点被黑"谁来兜底？——SecOC（L32）。 两者是分工关系，不是替代关系：

威胁谁挡
在网线上偷看内容MACsec（加密）
在网线上篡改/伪造帧MACsec（ICV）+ SecOC（认证码）
中间节点被黑后伪造/篡改报文SecOC——发送 ECU 加认证码，目标 ECU 端到端验证，中间节点转发时不用解密内容
重放MACsec（PN 窗口）+ SecOC（新鲜值）
CAN 总线上的报文（MACsec 管不到）SecOC——跨 CAN/以太网异构总线端到端
一句话：MACsec 护"路"（每段网线加密），SecOC 护"信"（报文端到端可信）。关键控制报文两道都上。

部署建议：开在"信任边界"上——网关 ↔ 域控的骨干链路、T-BOX 对外出口、OBD/诊断入口（L51 的 DoIP 诊断仪就从这儿进来），两端成对开启（一端开一端不开，就只能退回明文或直接丢帧）；传感器末梢的短链按成本与风险取舍。

六、和 TSN 兄弟们怎么共处（呼应 L47~L51）

MACsec 不是孤立的，它和前面几课的二层机制在同一块交换机芯片里协同工作：

  • 帧变胖了：每帧最多增加约 32 字节（SecTAG 8~16B + ICV 8~16B）。端口允许的帧长要留足余量——别把 MTU 卡死在 1500。
  • 信封地址保持明文：DA/SA/VLAN 标签/优先级 PCP 都不加密——所以 L49 的 VLAN 分流与流分类、L47 的 Qbv 门控、L50 的 FRER 去重照常工作（它们读的都是明文的信封信息）。加密的是"信纸"，不影响"邮局分拣"。
  • 硬件 offload：车载交换机芯片里集成 MACsec 引擎，AES-GCM 线速完成、时延固定——软件加密的抖动会毁掉 TSN 的确定性预算（Qbv 门控和 gPTP 校时都怕抖动）。
  • gPTP 校时帧要不要也上锁？ 一道工程选择题：上锁能防"改全车时钟"的攻击（时钟被改乱 = TSN 调度错乱 + 安全新鲜值失效），但要求加解密时延固定、时间戳在解密后再打；也有设计让 PTP 走明文通道图省事。

把 L47 以来的"车载以太网深度系列"串一遍：PHY（L48）把比特送上线 → 出口 MACsec 上锁、入口开锁（本课）→ 交换机（L49）按明文头分流 → Qbv（L47）准时出门 → FRER（L50）关键帧双发去重 → 诊断/OTA（L51）在加密的骨干上跑。给全车流量当"链路保安"的，就是 MACsec。

和 L51 呼应：DoIP 的路由激活（0x0005）是应用层的门禁，MACsec 是链路层的门禁——诊断仪想进车干活，两道门都得过。

七、三条铁律（记住这三句）

  1. 最底层的一把锁：MACsec 在链路层给"整条网线上的所有帧"加密 + 防篡改 + 防重放——不分单播/组播/广播、不分 IP 还是非 IP、不分哪个应用，对上层完全透明，一个字节都不用改。
  2. 一段一锁，不是一车一锁：帧每过一个端点就解密重加密，中间节点（网关）是可信明文点；要防"节点本身被黑"，靠 SecOC 做端到端报文认证补位——MACsec 护"路"，SecOC 护"信"。
  3. 钥匙分层、常换、藏好：CAK 长期主钥锁在 HSM；MKA 协商分发 SAK 短期数据钥并定期无缝轮换（换钥不停机）；PN + 滑动窗口挡住重放。

八、费曼简答题（用自己的话，不许用术语）

Q1：用"寄信"打比方，讲一讲：车里的数据要防偷看，为什么"给每个应用单独上锁"（像 TLS 那样）不够，非要在"网线"这一层给所有信件统一上锁？MACsec 这把锁能罩住哪些"别的锁罩不住"的信件（举两种）？它又管不到哪一段路？（提示：想想组播/广播、时间同步帧，以及"相邻两个节点之间"）

Q2：偷听者把一辆车网线上的一段合法流量原样录了下来，想找机会重放出来骗系统"再执行一次"。接收方凭什么能认出这是"旧录像"而不是新消息？另外：为什么加密数据的钥匙（SAK）要隔一段时间就换一把？长期主钥匙（CAK）又为什么要锁在"保险柜"（HSM）里、从不直接拿出来加密数据？（提示：包序号 PN、滑动窗口、换钥匙不停机）

Q3（进阶）：中央网关把一段 MACsec 加密链路的数据转发到另一段也加密的链路时，它自己必须能"看"到明文——这是不是设计漏洞？如果需求是"从发信 ECU 到收信 ECU 全程谁都不能看内容"，光靠 MACsec 做得到吗？还缺哪一层？（提示：逐跳 vs 端到端；回想 L32 的 SecOC——认证码由谁加、由谁验、中间节点要不要解密？）
