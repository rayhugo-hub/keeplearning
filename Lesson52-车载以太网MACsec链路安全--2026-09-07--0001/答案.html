车载以太网 MACsec 链路安全——同一根网线上的数据，凭什么偷不走、改不了、重放不了？

费曼简答题参考答案

Q1：用"寄信"打比方，讲一讲：车里的数据要防偷看，为什么"给每个应用单独上锁"（像 TLS 那样）不够，非要在"网线"这一层给所有信件统一上锁？MACsec 这把锁能罩住哪些"别的锁罩不住"的信件（举两种）？它又管不到哪一段路？（提示：想想组播/广播、时间同步帧，以及"相邻两个节点之间"）

核心思路：锁要加在"所有信件都要经过的那一段公共通道"上——链路层；MACsec 罩住整条网线上的所有帧，但只管相邻两个端点之间的这一段。

① 为什么"给每个应用单独上锁"不够：

  • TLS 只保护"愿意接入的单个 TCP 应用"（比如 OTA 下载的 HTTPS），每个应用要分别改造、单独建会话；其他应用一概不管。
  • 可车里大量关键流量根本不是"一个 TCP 应用"：SOME/IP 服务发现（L39）是 UDP 组播；gPTP 时间同步（L47）是 EtherType 0x88F7 的非 IP 二层组播；诊断功能寻址（L51）是广播；摄像头/雷达是海量 UDP——TLS 统统罩不住。
  • IPsec 主要护 IP 单播，对组播/广播和非 IP 帧有盲区。上层锁的共性毛病：挑协议、挑应用。

② MACsec 为什么行： 它工作在链路层，在网卡/交换机端口上给"凡是走这条网线的以太网帧"统一加密——不挑协议、不挑应用、不挑单播还是组播；而且对上层完全透明：IP 地址不用改、应用一个字节都不用改，应用甚至不知道自己正被加密。一次部署，整条链路的流量全受益。

③ 它的边界： MACsec 只管"相邻两个 MACsec 端点之间的这一段网线"——不是端到端。帧每过一个端点（交换机端口、网关）就要解密 → 处理 → 重新加密，每段网线各上一把独立的锁。

结论（类比落点）： TLS 像"寄件人给某几封信单独糊蜡封"，MACsec 像"整条邮路配武装押运 + 加密车厢"——前者管不到其他信件，后者所有信件一起罩住；但押运只负责"这一段路"，送到下一个中转站就交接给下一班的押运。

Q2：偷听者把一辆车网线上的一段合法流量原样录了下来，想找机会重放出来骗系统"再执行一次"。接收方凭什么能认出这是"旧录像"而不是新消息？另外：为什么加密数据的钥匙（SAK）要隔一段时间就换一把？长期主钥匙（CAK）又为什么要锁在"保险柜"（HSM）里、从不直接拿出来加密数据？（提示：包序号 PN、滑动窗口、换钥匙不停机）

核心思路：防重放靠"每帧唯一的编号 + 收方滑动窗口"；防长期泄露靠"短期钥匙勤换 + 长期钥匙锁保险柜"。旧录像两头都对不上：序号过时、钥匙过期。

① 凭什么认出"旧录像"——PN 包序号：

  • MACsec 每一帧都带一个单调递增的 PN（包序号），发一帧加一；
  • 接收方维护一个滑动窗口，只认"比自己当前进度新一点"的帧；
  • 重放的旧帧，PN 要么在窗口里已经见过（重复），要么远落后于窗口下沿（太旧）——直接判为旧帧丢弃。

类比：电影票根每次撕一个号，拿昨天的票根再进场，检票员一看号码早就用过了。

② 为什么 SAK 要定期换：

  • 用越久泄露风险越大：同一把钥匙加密的流量越多，被分析、被破解的样本越多；
  • PN 会耗尽：PN 只有 4 字节，高速链路上很快转完一圈（这正是 XPN 用 8 字节序号的原因）；
  • 限制损失面：万一某把 SAK 真被破解，损失只限在它短暂的任期内，过期作废。
  • 换钥匙不停机：钥匙服务器通过 MKA 先把新 SAK 分发到所有节点，新旧并存一小段（TCI/AN 里的 AN 0~3 四个槽位就是干这个的），等全员确认切换到新钥匙后再废弃旧的。换完之后，用旧钥匙加密的帧在新钥匙期连 ICV 校验都过不了——所以就算偷听者录了整段流量，过一阵子再重放，序号和钥匙两头对不上。

③ CAK 为什么锁保险柜： CAK 是总根、极少更换——一旦泄露，整条链路的加密体系都要重建。所以它出厂就预置在 HSM（硬件安全模块，L32） 里，只参与派生 KEK/ICK，从不直接出来加密数据；日常干活的 SAK 即使被偷，也很快过期，损失面小。类比：CAK 是保险柜里的总钥匙，SAK 是每天发的临时门禁卡——总钥匙不出保险柜，临时卡天天作废。

结论： 防重放 = PN + 滑动窗口（每帧有唯一且递增的编号）；防泄露 = 钥匙分层 + SAK 勤换 + CAK 锁 HSM。录下来的"旧录像"既过不了序号关，也过不了钥匙关。

Q3（进阶）：中央网关把一段 MACsec 加密链路的数据转发到另一段也加密的链路时，它自己必须能"看"到明文——这是不是设计漏洞？如果需求是"从发信 ECU 到收信 ECU 全程谁都不能看内容"，光靠 MACsec 做得到吗？还缺哪一层？（提示：逐跳 vs 端到端；回想 L32 的 SecOC——认证码由谁加、由谁验、中间节点要不要解密？）

核心思路：网关看明文是"逐跳架构"的必然，不是漏洞；MACsec 护"路"、SecOC 护"信"，两者分层分工。要"全程谁都不能看"，光靠 MACsec 做不到。

① 网关为什么必须看明文——这是架构使然，不是漏洞：

  • MACsec 是"一段一锁"的链路层加密，网关是每一段的端点；
  • 网关要按内容干活：三层路由要看 IP、SOME/IP 要看服务、诊断要翻译（L51 的网关翻译官）——它本来就必须处理内容，是设计上被信任的"明文点"；
  • MACsec 防的是"网线上的人"（偷看、篡改、重放），防不了"节点本身被黑"；
  • 补充细节：纯二层交换机只看明文的信封地址（DA/SA/VLAN）就能转发密文帧、不一定要解密；但只要设备要"读内容"，解密就躲不掉——它也随之成为可信明文点。

② 光靠 MACsec 做不到"全程谁都不能看"： 帧每过一跳（网关）都会现出明文，只要中间有一跳被攻破，内容就暴露。想"从源 ECU 到目标 ECU 谁都不能看"，只能在上层做端到端加密（应用层 TLS 或专用加密）——但那要逐个应用改造，又回到 Q1 的"挑应用"老问题。

③ 工程解法：分层分工——MACsec 护"路"，SecOC 护"信"（L32）：

  • MACsec：逐跳加密，挡"偷看网线的人"，解决机密性；
  • SecOC：报文级端到端认证——发送 ECU 在报文里加认证码，目标 ECU 端到端验证，中间网关转发时不需要解密内容也能转发；
  • 即使某个中间节点被黑、想伪造或篡改报文，目标 ECU 一验认证码就识破——解决"节点本身被黑"的可信问题；
  • SecOC 还能跨 CAN 总线（MACsec 管不了 CAN），异构总线端到端都能护。

结论（类比）： 每段路配武装押运（MACsec）挡路上的劫匪，货物本身再贴防伪封条（SecOC）——就算某个押运点被收买、把货调了包，收货方验封条也能发现是假货。关键控制报文两道都上。

选择题答案

MCQ1：车内骨干链路的"防偷看"，为什么普遍选 MACsec（链路层），而不是只靠 TLS 或 IPsec？

✅ B. MACsec 工作在链路层，能保护这条链路上经过的所有以太网帧——包括 UDP 组播（如 SOME/IP 服务发现）、非 IP 的 gPTP 时间同步帧和广播，且对上层透明、应用无需改造；而 TLS 只管单个 TCP 应用，IPsec 对组播/广播和非 IP 帧都有盲区

解析：选型的关键是保护范围，不是速度。车里大量关键流量是 UDP 组播（SOME/IP 服务发现）、非 IP 的 L2 组播（gPTP 校时，EtherType 0x88F7）、广播（诊断功能寻址）——TLS 只管单个 TCP 应用、IPsec 对组播/广播和非 IP 帧有盲区，唯独链路层的 MACsec 能不分协议地罩住整条链路上所有帧，且对上层透明、无需逐应用改造。A 错：TLS/IPsec 也有硬件加速实现，"软件所以慢"不是主因，主因是保护范围；C 错：车内以太网照常跑 IP 协议栈（SOME/IP、DoIP、HTTP 都在 IP 之上），只是 MACsec 保护得不分 IP 与否；D 错：MACsec 恰恰给每帧增加 8~32 字节开销（SecTAG + ICV），选它是为了安全，不是为了省带宽。

MCQ2：偷听者在一条受 MACsec 保护的链路上录下大量密文帧，之后找机会把这些帧原样重放到同一条链路上，想骗接收方"重复执行"（比如再触发一次解锁）。接收方凭什么识破？

✅ B. 每一帧都带一个单调递增的包序号 PN，接收方用滑动窗口比对——序号重复的、远落后于窗口的帧直接丢；而且数据钥匙 SAK 会定期轮换，旧钥匙期加密的帧在新钥匙期连校验都过不了

解析：MACsec 的防重放是双层保险：① 每帧 PN 单调递增，收方滑动窗口查重——旧录像的 PN 要么重复、要么远落后于窗口，直接判旧丢弃；② SAK 定期无缝轮换——等偷听者找机会重放时，接收端早就切到新钥匙了，旧钥匙加密的帧连 ICV 校验都过不了。A 错：MACsec 没有"秒级时间戳"机制，PN 是序号不是墙钟时间（重放防御靠序号窗口，不靠对表）；C 错：每帧先问云端既不现实也不必要（车内链路是本地自治的，问云端反而引入新攻击面）；D 错：重放的帧源 MAC 和原帧相同，交换机不会因为 MAC 重复就拉黑（同源多帧是常态），识别重放是收方 MACsec 引擎的事，不是交换机的"拉黑"逻辑。

MCQ3：域控 A 与中央网关之间、中央网关与 T-BOX 之间，两段链路都开了 MACsec。关于"谁能看到明文"，以下哪个说法正确？

✅ C. MACsec 是"一段一锁"：中央网关是这两段链路的端点，它要把段①的帧解密、读内容转发、再用段②的钥匙重新加密——网关内部是明文（可信点）；若网关被攻破，经过它的内容都会暴露，所以要靠 SecOC 这类端到端报文认证兜底

解析：MACsec 是逐跳（hop-by-hop）加密：每段链路两端各是一把独立的锁（段①用 SAK-A、段②用 SAK-B），中央网关作为两段的共同端点，要读内容做路由/服务转发，必须先解密、再重新加密——网关内部是设计上被信任的"明文点"。所以"全程密文、谁都不能看"（A）、"只有最终收信方能看明文"（B）都不成立；被攻破的网关确实会让经过它的内容暴露，这正是要 SecOC 做端到端报文认证兜底的原因（目标 ECU 验认证码，中间节点被黑也伪造不了）。D 错：MACsec 帧仍是普通以太网帧，信封地址（DA/SA/VLAN）保持明文，交换机照常转发（纯二层转发甚至不需要解密）；MACsec 不是"禁止转发"，只是给载荷上锁。
