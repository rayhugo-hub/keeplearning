多传感器融合算法——三双"眼睛"如何合成一双"慧眼"？

← 上一课 ☰ 目录 下一课 →

一、先想想这个场景

深夜，暴雨，高速。你的车以 100km/h 巡航。前方 80 米处有一辆没开尾灯的事故车横在路中间。

  • 摄像头：雨滴散射光线，图像像蒙了毛玻璃——它"看见了"一团模糊的轮廓，但不敢确定那是什么
  • 毫米波雷达：穿透雨雾毫无压力，稳稳测出"前方 79.3 米有金属反射物"——但它分不清那是车、是护栏还是桥上铁皮
  • LiDAR：点云稀疏，雨滴产生大量噪点，但依稀能看出一个"宽 1.8 米、高 1.5 米"的实体

问题来了： 任何一个传感器单独看，都不够自信。但你的车却果断触发 AEB 紧急制动，稳稳刹停。它凭什么这么"确信"？

答案是多传感器融合（Sensor Fusion）。 三个传感器单独都是"偏科生"，但把它们的数据放在一起"商量"，系统就能得到任何一个传感器都给不出的高置信度结论。这是 L2+ 以上自动驾驶的"感知大脑"。想知道它们怎么"商量"的？往下看。

二、为什么要融合？——每个传感器都是"偏科生"

把三兄弟的"性格"摆在一起：

维度摄像头（Lesson 30）毫米波雷达LiDAR（Lesson 29）
强项语义：这是什么（车/人/标志/颜色）测距测速：多快、多远（多普勒）几何：精确的 3D 位置和形状
弱项无光/雨雾失效、测距靠"猜"无语义、角分辨率低（分不清轮廓）稀疏、无颜色、雨雾噪点多、贵
失效模式光照/天气金属多径反射（护栏、隧道）恶劣天气、远距离稀疏
成本低（$30-80）中（$50-200）高（$200-5000+）

核心洞察： 三兄弟的失效场景几乎不重叠。摄像头怕的（黑天雨雾），雷达不怕；雷达怕的（多径反射），摄像头和 LiDAR 能纠偏。融合的本质是用冗余换可靠——任何一个传感器"掉线"，系统仍然安全。

三、融合的三个层次——从"拼数据"到"拼结论"

融合不是简单地把数据倒在一起，业界按抽象程度分为三个层次：

flowchart TB subgraph L1["层次一：数据级融合"] D1["原始像素 + 原始点云 + 原始回波
逐像素/逐点对齐后合并
信息最全，但计算量巨大"] end subgraph L2["层次二：特征级融合"] F1["各自先提取特征（目标框/点云聚类）
再把特征列表合并、关联、去重
主流方案，兼顾信息量与算力"] end subgraph L3["层次三：决策级融合"] C1["每个传感器独立出结论
再投票/加权表决
最鲁棒，但细节信息丢失"] end D1 --> F1 F1 --> C1

三种层次的通俗理解

层次打个比方优点缺点车载使用
数据级三张照片叠在一起看信息零丢失算力爆炸、对齐要求苛刻❌ 极少
特征级三个人各自圈出"疑似目标"，再对名单信息与算力平衡目标关联（谁和谁是同一个）容易出错✅ 主流
决策级三个人各自表态"刹/不刹"，再举手表决最抗单个传感器故障融合前细节已丢失⚡ 常用兜底

四、融合的两大"地基"：空间对齐 + 时间同步

任何融合算法，前提都是："摄像头里的那个像素"和"雷达里的那个点"说的是同一个物理物体。这需要两步：

① 空间对齐（外参标定）

每个传感器的坐标系原点不同（装在车头/车顶/后视镜），要先通过标定求出外参矩阵（旋转 R + 平移 t），把所有传感器数据变换到同一个车身坐标系：

flowchart LR CAM["摄像头坐标系
(2D 像素)"] -->|"外参 R,t"| BODY["车身坐标系
(统一基准)"] RADAR["雷达坐标系
(3D 球坐标)"] -->|"外参 R,t"| BODY LIDAR["LiDAR 坐标系
(3D 点云)"] -->|"外参 R,t"| BODY BODY --> FUSION["融合算法"]

标定不准的后果很直观：摄像头说"前方 50 米有行人"，雷达说"前方 48 米有目标"——如果两个坐标系没对齐，融合算法会把它们当成两个目标，虚警频出。

② 时间同步

  • 摄像头 30fps（33ms 一帧）、雷达 20fps（50ms 一帧）、LiDAR 10fps（100ms 一帧）
  • 一辆 100km/h 的车，100ms 内移动 2.8 米
  • 如果不做时间同步，融合时把"0ms 的雷达数据"和"100ms 的摄像头数据"当同一时刻用，位置误差可达米级

工程做法： 所有传感器数据打上硬件时间戳，融合前按时间戳插值/外推到同一时刻（常用"最近邻 + 线性插值"），或者用预测模型把所有数据推到"当前时刻"。

五、核心算法：卡尔曼滤波——"预测 + 修正"的循环

特征级融合最经典的算法是卡尔曼滤波（Kalman Filter）。它不神秘，本质就是一个无限循环的"预测-修正"：

flowchart LR subgraph PRED["预测步 (先验)"] P1["用运动模型外推：
上一帧位置 + 速度 × Δt
→ 预测本帧位置"] end subgraph UPD["更新步 (后验)"] U1["拿传感器实测值
与预测值加权平均
权重 = 各自不确定度"] end P1 --> U1 U1 --> P1

用一个"猜球"的例子讲透

  1. 预测：你闭着眼，根据球上一秒的速度猜它现在在哪——猜的位置有误差（不确定度大）
  2. 测量：你睁开眼瞄一眼，传感器给了个实测位置——测量也有误差（比如雨雾天误差大）
  3. 融合：卡尔曼滤波做的事就是按不确定度加权平均：谁更可信，就多信谁
    • 雨雾天：摄像头误差大 → 权重小，多信雷达
    • 晴天：摄像头误差小 → 权重大
  4. 循环：融合结果作为下一轮的"上一帧"，继续预测→测量→修正

为什么叫"滤波"？ 因为它能把传感器数据里的噪声（毛刺）滤掉，输出的轨迹平滑且贴合真实运动。这是单传感器永远做不到的。

六、三条要记住的规则

📌 规则一：融合的本质是"取长补短"，不是"求平均"

平均是"三个臭皮匠各说各话取中间值"；融合是"谁在这个场景更可信就多听谁的"。雨雾天多信雷达，晴天多信摄像头——权重随场景动态变化，这才是融合的灵魂。

📌 规则二：没有"空间对齐 + 时间同步"，融合就是灾难

坐标系没对齐 → 一个目标被当成两个；时间没同步 → 位置差好几米。标定和同步是融合的地基，地基不稳，算法再高级也是空中楼阁。

📌 规则三：冗余不是浪费，是安全的底线

纯视觉方案赌的是"数据够多、算法够强"；多传感器融合赌的是"任何单一传感器失效，系统仍安全"。L3 以上法规要求有独立的冗余感知通道——这就是融合存在的法规级理由。
