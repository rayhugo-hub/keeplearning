一、先想想这个场景

一辆舱驾一体车上，同一时刻正在发生这些事：

  • 智驾系统在高速上做决策（毫秒级，出错可能出人命）；
  • 副驾在看4K 视频（后台还在下载更新包）；
  • 语音助手在听你说话；
  • 仪表盘在刷新 120Hz 的画面。

它们全都挤在同一颗芯片上——抢 CPU、抢内存、抢总线带宽。那问题来了：

  • 视频下载把 CPU 占满了，智驾会不会卡顿？
  • 一个应用写错了内存地址，会不会把仪表的数据踩坏？
  • 娱乐流量把以太网堵死了，关键报文会不会丢？
这一课讲清楚：域控制器靠"资源隔离 + QoS"，让安全关键任务和普通应用共享一颗芯片，却互不拖累——关键任务"独占 + 高优先 + 预算保障"，普通任务"尽力而为"。

二、混合关键性：为什么必须隔离？

1. 什么是"混合关键性"（Mixed-Criticality）？

一颗芯片上，同时跑着安全关键功能（ASIL-D，如智驾决策、仪表显示）和无安全要求的功能（QM，如娱乐、OTA 下载）。不同安全等级的任务共享同一份硬件资源，这就是混合关键性场景。

2. 不隔离，会怎样"传染"？

共享资源不隔离的后果类比
CPU娱乐应用占满核 → 关键任务延迟抖动，错过截止时间有人霸占电梯，急救人员上不去
内存一个应用越界写 → 踩坏关键任务的数据，系统崩溃一户漏水，淹了整栋楼
总线带宽视频下载占满带宽 → 关键报文丢失或超时卡车堵住高速，救护车过不去

结论：混合关键性的核心矛盾 = "共享"与"安全"的矛盾。解决思路就两个字——隔离。

三、三维隔离：时间、空间、带宽

1. 时间隔离（CPU 调度）——"排班表"

管的是：任务什么时候能跑、能跑多久。

手段做法说明
固定绑核（CPU pinning）关键 VM 的 vCPU 独占物理核智驾独占 4 个核，娱乐永远抢不走
静态优先级关键线程用最高优先级（如 SCHED_FIFO）高优先级任务先跑，低优先级靠边
周期预算每个周期内给任务分配固定时间窗如每 1ms 周期，关键任务固定 0.2ms

类比：像医院的"手术排班表"——急诊手术永远有固定时段和最高优先权，普通门诊排队等。

2. 空间隔离（内存）——"隔断墙"

管的是：任务能碰哪些内存区域。

手段做法说明
MMU 虚拟地址隔离每个 VM 有独立地址空间互相看不见、摸不着
内存 carve-out关键 VM 独占物理内存区域物理上划死，谁也不能动
IOMMU / SMMU限制外设 DMA 的访问范围摄像头、网卡只能读写"自己家"的内存
IOMMU（也叫 SMMU）特别重要：外设（摄像头、以太网控制器）用 DMA 直接读写内存，绕过 CPU。如果没有 IOMMU，一个被攻破或出错的外设可以直接读写整个内存——这是严重的安全漏洞。IOMMU 相当于给每个外设发了一张"房产证"，只许进自己家。

类比：合租公寓里每户有独立房间，墙是实的（隔断墙）；物业还规定：快递员（外设）只能把包裹放你家门口，不能进别人房间。

3. 带宽隔离（通信）——"专用车道"

管的是：数据能用多少带宽、什么时候能发。

手段做法说明
TSN 802.1Qbv（时间感知整形）给关键流量固定时间窗时间窗内只有关键报文能发，绝不拥堵
TSN 802.1Qav（基于信用整形）给普通流量限速普通流量有"信用额度"，用完就等
802.1Q 优先级队列关键报文打高优先级标签交换机先转发高优先级
CAN 仲裁报文 ID 优先级ID 越小优先级越高（静态设计）

类比：高速上的"应急车道"——救护车永远有专用通道，普通车排队但不会被堵死。

QoS（Quality of Service，服务质量）的本质：不是让所有任务都快，而是保证关键任务的关键指标——延迟有上界、带宽有下限、资源有保障。

最后一道防线

万一隔离被突破（bug、攻击、硬件故障），还有 看门狗（Watchdog）+ E2E 保护 + 健康监控：发现异常 → 上报 → 降级/复位，把损失控制在最小。隔离是"预防"，监控是"兜底"。

五、三条铁律（记住这三句）

  1. 隔离是"物理边界"，QoS 是"通行规则"——隔离把问题关在单间里，QoS 保证关键任务优先通行。
  2. 三个维度缺一不可——时间隔离管"什么时候跑"，空间隔离管"能碰哪里"，带宽隔离管"能用多少"。
  3. 关键任务"独占 + 高优先 + 预算保障"，普通任务"尽力而为"——这是混合关键性系统的黄金法则。
