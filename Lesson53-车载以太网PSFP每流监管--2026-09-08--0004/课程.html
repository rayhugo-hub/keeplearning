一、先想想这个场景

车里骨干网上同时跑着：一路 4K 摄像头视频流、一路激光雷达点云、一路转向控制报文。突然，某个传感器 ECU 的软件出了 bug——更糟的情况是被远程攻破（L32/L52 那种威胁）——开始"发疯"：

flowchart LR CAM["📷 摄像头流（80 Mbps，守规矩）"] LID["🔦 雷达点云（40 Mbps，守规矩）"] BAD["😈 传感器 ECU（发疯：乱发 + 超大帧）"] SW["交换机 → 骨干链路"] DST["🛡️ 智驾域控 / 中央网关"] CAM --> SW LID --> SW BAD ==> SW SW --> DST

它拼命往网络里灌数据、在不该发的时间发帧、发超过允许长度的超大帧。结果：链路拥塞、交换机缓冲区被塞满，转向/制动这些关键控制帧要么被挤掉、要么迟到几毫秒。几毫秒对娱乐系统无所谓，对正在自动变道的车就是事故。

可车上不是有 Qbv 门控（L47）、有队列优先级（L49）吗？怎么还防不住？——因为它们的设计前提都是"发送者守规矩"。守规矩的车流排队等绿灯当然没问题；可如果有一辆车闯红灯、逆行、超载，光靠"绿灯时序"是拦不住它的。这时候需要的是交警：把每一辆车认出来，谁违章就拦谁——而不是把整条路的所有车都限速。

这一课讲的就是这位"交警"：PSFP（Per-Stream Filtering and Policing，每流过滤与监管，IEEE 802.1Qci）——在交换机的入口处，按每一条数据流单独设卡限流。

二、为什么"一把总闸"不够——粒度与位置

先看看 L47/L49 已经装好的机制，它们都管不住"发疯的源"：

已有机制管的单位守的位置前提 / 短板
队列 + 优先级（L49）按优先级"类"，一管一大片出口队列同一类的好流坏流连坐：坏流把缓冲塞满，好帧一起被挤掉
Qav 按类整形（L47）流量类别（AVB 类 A/B）出口同类共享信用额度，坏流可以吃光整类配额，正常流被饿死
Qbv 门控（L47）整个端口的队列出口假设"源都守规矩、只在时间窗内发"；坏帧已经进交换机、占过资源了，它只能让剩下的好帧"晚点走"，救不回被挤掉的
端口级限速一个端口上所有流入口/出口一刀切：一路视频超速，同端口别的流全被误伤
PSFP（本课）每一条数据流交换机入口不信任任何源：逐流点名执法

两个关键差异：

  • 粒度——"班级管理" vs "点名到人"。队列、类别、优先级都是"一群人合管"：一个班有人捣乱，全班罚站。PSFP 管的粒度是一条流——精确到"哪台设备发往哪个目标、带哪个 VLAN 标签的哪一路数据"（比如"左前摄像头 → 智驾域控的视频流"）。谁撒野掐谁，好流不连坐。
  • 位置——"进门查" vs "出门查"。之前那些闸大多守在"出门"的地方，管"怎么出门、何时出门"。PSFP 守在进门的地方：坏帧在占用交换资源之前就被掐掉——不占队列、不挤好帧、不占链路。
类比：Qbv 像红绿灯（按时刻放行守规矩的车流），PSFP 像进隧道前的交警检查站——超载、超长、闯禁行的车，在进隧道前就被拦下，而不是等它进去堵死整条隧道再处理。

三、PSFP 三板斧——过滤器、流门、流量计

PSFP 由三个组件组成，前面还有一个"认人"的步骤。一帧数据进入交换机入口后，要过这四道程序：

flowchart LR IN["入口帧"] --> ID["① 流识别：认出是哪条流<br>（按 DA/SA/VLAN/优先级，和 L50 FRER 同一套工具）"] ID --> F["② 流过滤器：查白名单 + 最大帧长"] F --> G["③ 流门：按时间表开/关"] G --> M["④ 流量计：双速率三色令牌桶"] M --> OK["✅ 放行 → 进转发引擎"] F -- "名单外 / 超长帧" --> DROP["🗑️ 丢弃"] G -- "门关着到达" --> DROP M -- "染红：超速超量" --> DROP

前置：流识别（Stream Identification）——先认出"这是哪条流"。 靠什么认？和 L50 的 FRER 是同一套工具（802.1CB 定义的流识别函数）：用目的/源 MAC、VLAN 标签、优先级，甚至 IP 层信息组合出一个"流 ID"。认出了流，才知道该拿哪一套规则来管它。

关卡管什么怎么管类比
① 流过滤器（Stream Filter）这帧"够不够格"白名单：没登记的流直接丢；最大帧长（max SDU）检查：超长的帧直接丢；动作可选：放行 / 丢弃 / 改道 / 计数门卫：查证件 + 量尺寸
② 流门（Stream Gate）这帧"是不是该出现的时间"每条流一份门控列表（和 Qbv 同款语法）：按时间表开/关；门关着时到达的帧直接丢弃；开门期间还带字节配额，超配额的部分也丢限时通行证：非通行时段一律拦下
③ 流量计（Flow Meter）这流"有没有超速"双速率三色令牌桶：绿（承诺内）放行、黄（超承诺但有超额额度）按配置丢或打标、红（超全部额度）丢弃按车限速：超速部分吃罚单

三条防线各管一摊，互不替代：

  • 超长帧（比如一个 ECU 发出 3000 字节的帧，超过了这条流允许的最大帧长）——过滤器拦；
  • 时间窗外乱发（这条流被分配了 5ms 周期里的 1ms 窗口，它却在窗口外猛发）——流门拦；
  • 总速率超限（平均速率超过分配给它的带宽）——流量计拦。
标准依据：IEEE 802.1Qci-2017，后并入 IEEE 802.1Q-2018，是 TSN 家族成员，也被车用以太网 profile（IEEE 802.1DG）纳入。

四、双速率三色令牌桶——怎么"数币"限流

流量计（Flow Meter）用的算法叫双速率三色标记（Two-Rate Three-Color Marker），核心是两个装"币"的桶：

参数含义通俗理解
CIR（承诺信息速率）每秒往绿桶里进币的速率"包月高速流量"的速率
CBS（承诺突发大小）绿桶的深度（最多攒多少币）高速流量没用的可以攒下来，供突发时一口气花
EIR（超额信息速率）每秒往黄桶里进币的速率超出高速部分，还有一点"低速流量"额度
EBS（超额突发大小）黄桶的深度低速流量能攒的额度

每一帧到达都要"付币"——付的币数等于帧的大小：

flowchart TB FR["📨 帧到达（要花 S 个币，S = 帧大小）"] --> D1{"绿桶有 S 个币吗？<br>绿桶按 CIR 进币，深度 CBS"} D1 -- "有" --> G["🟢 绿：正常放行，绿桶扣 S"] D1 -- "没有" --> D2{"黄桶有 S 个币吗？<br>黄桶按 EIR 进币，深度 EBS"} D2 -- "有" --> Y["🟡 黄：超出承诺部分<br>按配置丢弃或打标放行，黄桶扣 S"] D2 -- "没有" --> R["🔴 红：超出全部额度 → 丢弃"]
  • 🟢 绿 = 在承诺带宽内 → 正常放行；
  • 🟡 黄 = 超出承诺、但还在超额额度内 → 由配置决定：dropOnYellow 打开就直接丢；关着就放行，但可以打上"可丢"标记（之后拥塞时优先丢它）；
  • 🔴 红 = 两个桶都付不起 → 直接丢弃。

为什么桶深（CBS/EBS）很重要？——允许"短突发"。 视频流天然有尖峰：每过几秒的 I 帧瞬间能冲到平均速率的 1.5 倍。如果按"瞬时超过 80 Mbps 就丢"，视频会花屏。桶的妙处在于：平时速率低于 CIR 时，绿币越攒越多；I 帧来了，一口气花掉攒下的币——只要长期平均不超、桶没见底，短突发完全没问题。反过来，真发疯的源是持续超速：币只出不进（进的速率 CIR 远小于花的速率），桶迟早见底——持续超速逃不掉。

类比：绿桶像"流量包 + 结转"——这个月没用的高速流量结转到下个月，月底突击下载也能扛；但要是天天 24 小时满速下载，结转额度再大也会耗尽，超出的部分就得限速或断网。PSFP 的桶就是这么对付"持续发疯"的。

五、两道门的分工——入口"流门" vs 出口"总闸"（呼应 L47）

PSFP 的"流门"和 Qbv 的"门控"都带个"门"字，也很容易混——但它们本质不同：

Qbv 门控（L47）PSFP 流门（本课）
位置交换机的出口（egress）交换机的入口（ingress），转发之前
管的粒度一个端口的队列（按优先级类，一大片）单条数据流
门关着时帧在队列里等着，开门后继续走到达的帧直接丢弃（没有"等"的缓冲区）
本质调度器：决定好帧"何时出门"执法者：拦掉不该出现的坏帧
靠什么定时间gPTP 时间（802.1AS，L47）同一份 gPTP 时间
flowchart LR BAD["😈 发疯的源（乱发 / 超速 / 超长）"] -.-> X["🗑️ 交换机入口：PSFP 在此拦截"] CAM["📷 守规矩的摄像头"] --> IN["交换机入口：PSFP 放行"] IN --> Q["出口队列 + Qbv 门控（L47）"] Q --> DST["🧠 域控 / 网关"]

为什么两道门都要？ 一句话：Qbv 管"准点"，PSFP 管"资格"。

  • Qbv 的"总闸"在出口，可帧要走到出口，已经穿过交换机、占过队列和带宽了。遇到发疯的源，好帧在入口就已经被挤掉或挤迟到——Qbv 再准时，放行的也是"迟到队列里的幸存者"。
  • PSFP 在入口先把病流掐了：坏帧根本不进交换机 → 不占队列、不挤好帧 → Qbv 才能按时间表准点放行真正的好流。
  • 换句话说：Qbv 的前提假设是"源都守规矩"；PSFP 把这个假设变成了强制执法——不守规矩的帧，进不了场。

六、和 FRER、MACsec 兄弟怎么配合 + 工程要点

① 认流工具和 FRER 共用。 L50 的 FRER 要识别"同一条流"才能复制/去重，PSFP 也要识别"同一条流"才能设卡——两者用的是同一套流识别函数（802.1CB）。一套识别，两种用法：FRER 管"冗余"，PSFP 管"监管"。

② 帧长预算要把所有标签算上。 真车里的帧常常带着 VLAN 标签（L49）、FRER 的 R-TAG（L50）、MACsec 的 SecTAG（L52）——这些都会让帧"变胖"。配置流过滤器的"最大帧长"时，必须把各层标签的开销算进预算，否则合法的"胖帧"会被当成超长帧误杀。

③ 时间前提：先同步，再关门。 流门的时间表依赖 gPTP（L47）。整车刚上电、时钟还没同步时，门控列表不能严格执行——工程上要设计降级策略（先按"常开 + 只过滤帧长"兜底，时间同步建立后再启用时间窗），否则会把正常流量误杀。

④ 表项资源有限，别贪心。 过滤器、门、计量器都是交换机芯片里的硬件表项，数量有限。整车设计上只给关键流建卡：控制类报文、诊断/OTA（L51）、摄像头/雷达大流量。不是每条流都值得一个专属关卡。

⑤ 防的内容不同——PSFP 防"行为发疯"，防不了"内容伪造"。 PSFP 管的是"这条流有没有资格、守不守规矩"（超速、超长、时间窗外、名单外）；帧的内容是否被伪造篡改，是 SecOC（L32）/MACsec（L52）的活。两者是互补关系：PSFP 是行为门禁，MACsec/SecOC 是内容信任——关键流两道都上。

把 L47~L52 的系列串一遍（简化示意）： 摄像头帧的旅程——PHY（L48）把比特送上线 → MACsec（L52）开锁/上锁 → 交换机入口按 L49 的规则认出是哪条流 → PSFP（本课）按流设卡限流 → 转发引擎查表送向出口 → L47 的 Qav 整形 + Qbv 门控准点出门 → L50 的 FRER 在冗余路径上双发去重。PSFP 就是这条流水线上守在交换机"大门口"的检查站。

七、三条铁律（记住这三句）

  1. 点名到人，不搞连坐：PSFP 按每一条数据流过滤 + 限流（不是按类、不是按端口）——谁撒野掐谁，同队列的好流不受牵连。
  2. 三板斧各管一摊：过滤器管"身份与尺寸"（名单外、超长帧丢）、流门管"时间"（时间窗外到达的帧丢）、流量计管"速率"（双速率三色：绿放行 / 黄可丢 / 红丢弃）——短突发靠桶深吸收，持续超速必被拦。
  3. 位置与分工：PSFP 在入口执法（坏帧别进场、不占资源），Qbv 在出口调度（好帧准点走）；流识别与 FRER 共用一套工具；配帧长预算时把 VLAN / R-TAG / SecTAG 的开销全算上。

八、费曼简答题（用自己的话，不许用术语）

Q1：用"车流进隧道"打比方：为什么防止一条"发疯的数据流"堵死全车网络，不能只靠出口的排队调度（像 L47 的 Qbv），也不能只对"整条隧道"统一限速？PSFP 的过滤器、流门、流量计这三道关卡，分别相当于交警的什么检查？（提示：想一想"按类管会连坐好车"、"进门查 vs 出门查"，以及"查证件、限时段、限车速"分别对应谁）

Q2：摄像头视频流平均 80 Mbps，但每隔几秒会有一个瞬时大爆发（I 帧），瞬间冲到 120 Mbps——如果限速规则是"瞬时超过 80 就丢帧"，视频会花屏。令牌桶的"承诺速率（CIR）"和"突发额度（桶深 CBS/EBS）"分别是怎么解决这个问题的？反过来，如果一个 ECU 真发疯了、连续几分钟都按 120 Mbps 狂发，绿、黄、红三色分别怎么处理它？（提示：想想"攒币"与"桶见底"，短突发被吸收、持续超速逃不掉）

Q3（进阶）：Qbv 的门和 PSFP 的"流门"都带个"门"字，本质区别是什么？为什么门关着时，Qbv 的帧可以"等"，PSFP 的帧却要"丢"？如果一辆车只部署了 Qbv、没有 PSFP，一个被攻破的 ECU 乱发数据时会发生什么？（提示：一个管"何时出门"、一个管"能不能进场"；有没有缓冲区；想想好帧是怎么被挤掉的）
