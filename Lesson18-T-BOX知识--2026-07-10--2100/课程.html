一、先想想这个问题

你有没有拆过一台旧手机？里面有一块主板，上面焊着：一个主芯片（SoC）、一个通信基带（Modem）、一个 GPS 模块、一个 SIM 卡槽、一块电池管理芯片、各种接口——T-BOX 其实就是一台"车规级手机"，但比手机复杂得多。

对比项你的手机T-BOX
主芯片骁龙/天玑 SoC车规 MCU + 通信 SoC
通信4G/5G 基带4G/5G 车规级 Modem
定位GPS/北斗高精度 GNSS（双频、RTK）
SIM1张 SIM 卡eSIM + 外置 SIM 双备份
接口USB-C、WiFi、蓝牙CAN、以太网、LIN、蓝牙、WiFi
电源电池供电车载蓄电池 12V/24V（带掉电保护）
工作温度0°C~35°C-40°C~85°C
设计寿命2~3 年10~15 年

关键问题：T-BOX 本质上是一个"通信中转站"——它一边通过以太网和 CAN 总线连接车内网络，一边通过 4G/5G 连接云端。它的硬件架构直接决定了通信的稳定性、安全性和可靠性。

三、T-BOX 内部通信——所有芯片怎么"对话"？

T-BOX 内部并不是把所有芯片用一根线连起来——它有明确的内部总线架构。

3.1 MCU ↔ Modem：AT 指令通道

最核心的链路——MCU 通过 UART（串口） 向 Modem 发送 AT 指令：

MCU → AT+CGATT=1  (附着网络)
Modem → OK
MCU → AT+QIOPEN="TCP","mqtt.tsp.com",1883  (建立 MQTT 连接)
Modem → CONNECT

💡 AT 指令是"Hayes 命令集"的简称，最早用于电话调制解调器，今天仍然是车规 Modem 的标配控制协议。MCU 通过它控制 Modem 拨号、连接、发送数据。

sequenceDiagram participant MCU as 主控 MCU participant MODEM as 5G Modem participant CLOUD as TSP 云平台 MCU->>MODEM: AT+CGATT=1（附着网络） MODEM-->>MCU: OK MCU->>MODEM: AT+QIACT=1（激活 PDP 上下文） MODEM-->>MCU: OK MCU->>MODEM: AT+QIOPEN（建立 TCP 连接） MODEM-->>MCU: CONNECT MODEM->>CLOUD: TCP 三次握手 CLOUD-->>MODEM: SYN-ACK MODEM-->>MCU: +QIOPEN: 0,0 MCU->>MODEM: AT+QISEND=0,128（发送 MQTT 数据） MODEM-->>CLOUD: MQTT PUBLISH（车辆状态） CLOUD-->>MODEM: MQTT PUBACK MODEM-->>MCU: +QISEND: 0,128,OK

3.2 MCU ↔ GNSS：NMEA 0183 协议

GNSS 模组通过第二个 UART 口以 NMEA 0183 协议 每秒输出定位数据：

$GPGGA,123519,4807.038,N,01131.000,E,1,08,0.9,545.4,M,46.9,M,,*47

MCU 解析后得到：时间、纬度、经度、高度、卫星数、精度因子——然后打包成 MQTT 消息上云。

3.3 MCU ↔ HSM：SPI 总线

HSM（硬件安全模块）通过 SPI（高速同步串口） 与 MCU 通信，完成：

  • 安全启动验证：MCU 启动时，HSM 校验 Bootloader 签名
  • TLS 握手加速：云端连接时，HSM 在硬件内完成证书签名验证
  • CAN 报文加解密：安全网关场景下实时加解密 CAN 消息

SPI 的速率（10~50MHz）远高于 UART（通常 115200bps），适合大数据量的加解密操作。

3.4 MCU ↔ 车内网络：以太网 + CAN

总线用途数据量典型消息
车载以太网连接 HPC/网关，传输大数据（OTA 包、日志、高精地图）100Mbps~1GbpsOTA 镜像文件、诊断日志、高清地图增量

四、T-BOX 的电源管理——汽车熄火了它还在工作？

T-BOX 一个独特的需求：车停了，T-BOX 不能关机。

场景电源状态T-BOX 行为
车辆行驶发电机供电 + 蓄电池充电全功能运行：数据上报、云连接、诊断监控
车辆熄火（IVR 模式）蓄电池 12V 直供，PMIC 降压灵魂拷问：熄火了怎么不掉电？
深休眠蓄电池，PMIC 关闭大部分外设仅 RTC + 唤醒电路工作，待机电流 < 1mA
远程唤醒蓄电池，Modem 低功耗待机云端发 SMS/数据包 → Modem 检测到 → 通过 WAKE 引脚唤醒 MCU

T-BOX 熄火不掉电的秘密

flowchart LR BATT["12V 蓄电池<br>（KL30 常电）"] --> PMIC["PMIC"] PMIC -->|全功能模式| FULL["主控 + Modem + 接口<br>200~500mA"] PMIC -->|深休眠| SLEEP_ON["仅 RTC + 唤醒<br>< 1mA"] WAKE["唤醒信号<br>CAN / Modem / ACC"] -.->|触发唤醒| PMIC SLEEP_ON -.->|收到唤醒| FULL

关键设计：T-BOX 接入的是汽车常电（KL30）——熄火后蓄电池仍然供电。PMIC 在深休眠模式下只保留 RTC 和唤醒电路的电，待机电流控制到 1mA 以下（相当于一个 LED 指示灯），以保证停放 30 天不会亏电启动不了车。

五、三条核心规则

#规则一句话
1T-BOX = 车规级"手机主板"主控 MCU + 5G Modem + GNSS + eSIM + HSM + 电源管理——六大模块缺一不可，每颗芯片都必须通过车规认证
2内部靠 UART/SPI 对话，外部靠以太网和 CAN 出行MCU 通过 UART 发 AT 指令控制 Modem，通过 SPI 调用 HSM 加密；以太网连 HPC/网关，CAN 总线连车身域——各有各的通道，各司其职
3熄火≠关机——常电设计 + 深休眠 < 1mAT-BOX 一直挂在蓄电池上（KL30），深休眠时只保留 RTC + 唤醒电路；收到远程唤醒或 CAN 唤醒信号后瞬间恢复全功能运行
